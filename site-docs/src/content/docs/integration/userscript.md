특정 SNS 전용 기능이 아닙니다. 자신의 브라우저에서 **작성창과 버튼을 붙일 위치**를 지정해
NyatiDraw를 열고, 완료한 PNG를 가져오는 작은 버튼을 추가합니다. 계정 인증이나 별도 업로드 서버는 필요하지 않습니다.

:::caution[실험적 연동]
사이트마다 DOM 구조와 보안 정책이 다릅니다. 모든 사이트에서 버튼 삽입이나 이미지 붙여넣기가
되는 것은 아닙니다. 자동 첨부·자동 게시 기능은 제공하지 않습니다.
격리된 Edge에서 버튼 삽입·PNG 반환·복사·붙여넣기를 확인했습니다.
Tampermonkey/Greasemonkey를 실제 설치한 환경과 각 사이트 서버의 첨부 동작은 아직 별도 검증이 필요합니다.
:::

## 설치와 설정

1. 브라우저에 Tampermonkey 또는 Greasemonkey 같은 유저스크립트 관리자를 준비합니다.
2. [NyatiDraw 유저스크립트 설치](/nyatidraw/draw/integration/nyatidraw.user.js)를 열어 내용을 확인하고 설치합니다.
3. 사용할 **HTTPS 사이트**에서 관리자 메뉴의 NyatiDraw 설정을 엽니다.
4. 작성창 범위, textarea 선택자, 버튼 위치 선택자를 각각 입력하고 저장합니다. 버튼은 지정한 위치 요소 바로 뒤에 붙습니다.

기본 상태에서는 어느 사이트에도 버튼을 추가하지 않습니다.
설정은 현재 사이트의 정확한 origin에만 적용됩니다. 하위 도메인은 각각 설정합니다.
스크립트의 HTTPS 전체 실행 권한이 부담된다면 설치한 스크립트의 `@match`를 사용할 사이트로 좁힐 수 있습니다.

## 두 선택자는 별개입니다

예를 들어 대상 사이트가 아래와 같은 작성창을 사용한다고 가정합니다.

```html
<section class="composer">
  <textarea class="draft"></textarea>
  <div class="actions"><button>첨부</button></div>
</section>
```

| 설정 | 이 예제에서 넣을 값 |
| --- | --- |
| 작성창 범위 | `.composer` |
| textarea | `textarea.draft` |
| 버튼 위치 | `.actions` |

작성창이 여러 개라면 범위를 지정해 각 textarea와 버튼 위치를 같은 작성창 안에서 찾게 합니다.
여러 사이트에 쓸 수 있는 구성 방식이지, 위 예제 선택자가 모든 사이트에 맞는다는 뜻은 아닙니다.
`contenteditable`, iframe 내부, Shadow DOM 내부 편집기는 현재 대상이 아닙니다.

## 그림을 전달하는 흐름

1. 추가된 **그림 그리기** 버튼을 누르면 전체 UI의 NyatiDraw 팝업이 열립니다.
2. 그림을 그리고 **완료**를 누릅니다. 일반 웹판의 복구 그림과 분리된 임시 새 그림입니다.
3. 원래 페이지의 결과 미리보기에서 **PNG 복사**를 누릅니다.
4. 원래 textarea에 **Ctrl+V** 또는 기기의 붙여넣기를 사용합니다. 안 되면 **PNG 다운로드**로 첨부합니다.

유저스크립트는 작성하던 텍스트를 읽어 보내거나 덮어쓰지 않습니다.
돌아온 PNG를 사이트 서버에 자동 전송하지 않습니다. 붙여넣기·파일 첨부 시의 처리는 대상 사이트가 담당합니다.
결과를 보관하기 전에 호출 페이지를 닫거나 새로고침하면 이미지를 잃을 수 있습니다.

## 제한과 문제 해결

- **버튼이 없음**: 사이트 주소와 세 선택자를 확인하세요. 잘못된 범위는 엉뚱한 작성창을 찾게 할 수 있습니다.
- **팝업이 안 열림**: 브라우저 팝업 차단을 확인하세요.
- **완료 전달이 안 됨**: CSP·COOP 정책이나 관리자 sandbox 호환성에 영향을 받을 수 있습니다. 편집기에서 직접 PNG/NTDR을 다운로드하세요.
- **붙여넣기가 안 됨**: textarea 자체는 이미지를 담는 요소가 아닙니다. 대상 사이트에 이미지 붙여넣기 기능이 있어야 합니다. PNG를 내려받아 파일 첨부를 사용하세요.
- **사이트 개편 후 사라짐**: CSS 선택자를 다시 지정하세요. 이 연동은 대상 사이트의 공식 API가 아닙니다.

직접 만드는 사이트라면 DOM 선택자 대신 [웹 편집기 SDK](../embedding/)를 쓰는 편이 안정적입니다.
