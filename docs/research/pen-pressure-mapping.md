# 펜 입력 압력 매핑 조사

상태: 조사 제안. 구현·UI 변경 없음. 조사일: 2026-09-25.

## 조사 요약

필압 매핑은 두 계층으로 분리하는 편이 명확하다.

1. **전역 입력 보정**: 장치가 보고한 정규화 압력 `p`를 사용자 반응 곡선 `g(p)`로 바꾼다. 모든 압력 반응 브러시에 공통 적용한다.
2. **브러시 응답**: 보정된 압력에 각 브러시의 크기·농도(불투명도 등) 응답을 적용한다. 브러시가 어떤 속성에 압력을 쓸지와 최소값은 기존 브러시 설정이다.

기본 전역 곡선은 직선 `g(p)=p`로 둔다. 간단 프리셋은 **Soft**(같은 입력에서 더 큰 출력, 약한 필압에 빨리 반응)와 **Hard**(더 작은 출력, 강한 필압에서 반응) 두 개면 충분하다. 프리셋은 이름으로 고정하고 실제 곡선 정의를 버전 관리한다. 사용자가 시험영역에 짧은 약/중/강 획을 그리고 이전·새 설정을 비교할 수 있어야 한다.

현재 UI의 압력 스위치와 최소 비율은 곡선 편집이 아니다. `size_pressure` / `opacity_pressure`는 각각 축 적용 여부이며 `size_min_ratio` / `opacity_min_ratio`는 압력이 0에 가까울 때의 하한이다. 기존 라운드 브러시는 크기에 `sqrt(p)`를, 농도에 `p`를 적용한다. 펜슬 엔진도 압력 축별 하한을 적용하지만 그 뒤에 재질별 농도 계산이 있다. 전역 곡선은 이 브러시별 동작보다 앞선 정규화 압력 계층이어야 한다.

## 저장소 관찰

- `crates/input/src/lib.rs`: `StylusSample.pressure`는 원본 센서 축을 위한 `f32`; `with_normalized_axes`가 범위를 `[0,1]`로 제한한다. 압력 0 자체는 유효 값이다.
- `crates/input-platform/src/lib.rs`: Windows `Option<u16>` 압력은 `0..1024`로 정규화하고, 축 정보가 없을 때 `0.5`를 사용한다. 원시 이벤트에서는 `Some(0)`과 `None`을 구분하지만, 정규화한 `StylusSample`에는 축 미보고 여부가 별도로 남지 않는다. Begin에서 좌표 뷰포트를 고정하는 구조가 있다.
- `apps/web/src/browser.js`: 브라우저 포인터는 마우스 압력을 상수 `1`로, 그 외 포인터는 `event.pressure`로 보낸다. 전역 보정은 마우스 상수압력까지 바꾸지 않도록 입력 종류에 적용 범위를 둬야 한다.
- `crates/brush/src/lib.rs`: 엔진은 `StylusSample.pressure`를 받아 브러시별 크기/농도 응답을 계산한다. 압력 0에서 접촉 시작 여부를 추적하며 v4/v5 onset 동작과 샘플 재생 검사가 존재한다.
- 데스크톱은 `native_canvas.rs`에서 설정을 `BrushPreset`으로 전달한다. 웹은 `adapter.rs`에서 같은 프리셋 필드를 구성한다. 이 위치보다 앞선 공통 입력 경계가 전역 보정 후보지만, raw 샘플 보존과 재생 포맷을 먼저 결정해야 한다.
- `BrushEvaluator::begin`은 불변 프리셋을 획 토큰에 복사한다. 프로젝트 도구 상태는 브러시별 토글/최소값을 직렬화한다. 전역 곡선을 추가할 때도 획 시작에서 설정을 고정해야 진행 중 UI 설정 변경이 한 획의 중간 결과를 바꾸지 않는다.

## 의미·저장 제안

- **사용자 확정: 향후 필압 매핑은 앱 레벨에만 저장한다.** 프로젝트에서 곡선을 복원하거나 프로젝트 저장 시 곡선을 함께 저장하지 않는다. 기기별 세분화 여부는 미정이다.
- 도구·브러시 크기·불투명도·브러시별 필압 옵션은 별개다. 이 기존 도구 설정은 프로젝트 값 우선, 없으면 앱 마지막 값, 저장 시 양쪽 기록이라는 정책을 유지한다.
- 기존 획 재생에 현재 앱의 곡선을 다시 적용하면 안 된다. 향후 구현에서는 보정된 압력을 획의 실행 입력으로 기록하는 등의 재생 계약을 정한다. 이는 과거 획 결과 보존을 위한 기록이지, 프로젝트에 앱의 필압 매핑 설정을 저장하거나 복원하는 기능이 아니다.

## 입력·재생 위험과 경계

- Begin/Move/End/Cancel의 위상은 압력 매핑으로 바꾸거나 제거하지 않는다. 특히 raw 압력 0인 Begin은 hover나 무효 이벤트로 재해석하지 않는다. 접촉 시작 판단 및 압력 onset은 기존 브러시 엔진의 버전 계약으로 남긴다.
- 압력 없는 마우스 입력은 현행 웹 경로처럼 상수 `1`을 유지한다. 실제 펜에서 압력 축이 미지원/미보고인 경우를 `0.5`로 대체하는 현재 정책은 매핑 작업과 별도로 제품 의미를 명시해야 한다.
- 기존 기록은 입력 샘플 압력과 brush engine/preset 식별자를 이용한다. 보정 후 압력을 기록하면 원시 입력과 구분해야 하며, 재생 시 다시 매핑하면 이중 적용될 수 있다. 원시 입력 보존 필요성 및 기록되는 압력의 의미는 구현 전에 정한다. 프로젝트에는 매핑 설정을 저장하지 않는다.
- 제안 경계: 플랫폼 정규화 → 펜 전역 보정(획 시작에서 스냅샷) → 브러시별 속성 응답 → 렌더러. 전역 곡선은 `document/input/brush`의 플랫폼 중립 타입만 사용하고 UI·OS API 의존은 호스트 계층에 둔다. 저장 포맷과 구엔진 호환성은 구현 전 별도 ADR/마이그레이션 검토 대상이다.

## 공식 자료

- [Krita Tablet Settings](https://docs.krita.org/en/reference_manual/preferences/tablet_settings.html): 전역 입력 압력 곡선이 태블릿 감도를 전역적으로 soft/hard하게 만든다고 설명한다. Tablet Tester는 보정 전 raw 이벤트를 보여 준다.
- [Clip Studio Paint: Adjust pen pressure](https://support.clip-studio.com/en-us/faq/articles/20190228): 필압 설정에서 실제로 그려 조정값을 확인하고, 더 강하게/가볍게 조절하며 모든 도구에 적용하는 흐름을 설명한다.
- [Procreate: Apple Pencil, Pressure and Smoothing](https://help.procreate.com/articles/tIdR13-apple-pencil-pressure-and-smoothing): 전역 입력 압력→브러시 효과 그래프와 안정화 설정을 구분한다. 전역 곡선 변경이 브러시에 의도치 않은 영향을 줄 수 있다고 안내한다.
- [Procreate Brush Studio Settings](https://help.procreate.com/procreate/handbook/brushes/brush-studio-settings): 개별 브러시 압력 반응으로 크기·불투명도·흐름 등을 다루며, 전역 설정 이후의 브러시 동작 계층을 보여 준다.

## 결론

전역 압력 곡선은 현재의 압력 on/off 및 최소 크기/농도 제어와 독립된 입력 보정이다. 직선 기본값과 Soft/Hard 프리셋, 시험영역을 제안한다. 구현은 raw 압력 0과 마우스 상수 압력을 보존하고, 획 시작 설정 고정 및 과거 획 재생 의미를 기록 포맷에서 먼저 정의한 뒤 진행해야 한다.
