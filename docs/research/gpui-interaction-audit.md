# GPUI 전환 전후의 편집 동작

비교 기준은 공개 alpha.23의 Dioxus 편집기와 레이어 선택 표시를 수정한 로컬 GPUI 릴리스 빌드다. 아래의 두 표는 수정 전에 발견한 차이와 재현 방법을 기록한다.

## 수정 후 확인한 동작

- Edge에서 색상환으로 색을 선택한 직후 E를 누르면 도구 막대가 지우개 선택 상태로 바뀐다. 전체 선택을 만들면 캔버스 위에 선택 도구줄이 나타난다. 메뉴를 열고 Esc를 한 번 누르면 선택을 유지하고, 다시 누르면 선택을 해제한다.
- 타임라인의 세 프레임을 클릭한 결과와 Home, 오른쪽, End, 왼쪽 키로 선택한 결과를 비교했다. 활성 프레임은 차례로 1, 2, 3, 2가 됐고 프레임 순서는 유지됐다. 13프레임 문서에서도 Home과 End를 누르면 첫 페이지와 마지막 페이지가 따라왔다.
- 두 색으로 만든 참조 PNG를 열었다. 패널을 늘리자 이미지가 실제로 확대됐고, 색 채취를 누른 동안 포인터 아래 픽셀과 같은 색의 견본이 보였다. 손을 떼면 견본이 사라졌다.
- 최근 사용 목록에서 이미 밀려난 색이 고정된 상태로 시작했다. 핀을 풀면 고정 설정이 지워지고, 견본은 같은 자리에 남으며 현재 브러시 색도 유지됐다.
- Edge에서 캔버스 크기를 3×8로 적용하고, PNG의 세로를 4로 입력했다. 비율 50%, 가로 2, 세로 4가 함께 표시됐으며 다운로드한 PNG 헤더도 2×4였다. 브라우저를 새로고침한 후 작품 크기는 3×8이었다.
- 최종 WASM 빌드에서 새 그림에 획을 긋고 86,016바이트 NTDR을 내려받았다. Edge를 종료하고 새 프로필에서 열었을 때 하단 상태 표시를 제외한 868×812 영역의 픽셀이 저장 전과 모두 같았다.
- 1440×900 Edge에서 도킹 경계를 125px 끌어 놓고 다시 열었을 때 캔버스의 왼쪽 좌표는 409px로 유지됐다. 경계에 포커스를 둔 뒤 방향키를 누르면 421px로 이동했다. 768×750에서는 양쪽 패널을 전환하거나 접어도 캔버스 상단이 44px로 유지됐다.
- Edge에서 1번 레이어를 선택한 채 2번 행의 색 조정을 열었다. 밝기 손잡이를 누른 동안 1번 선의 RGB는 (137, 69, 69)를 유지했고, 2번 선만 (255, 245, 245)로 바뀌었다. 초기화와 취소 후 원래 색으로 돌아왔다. 보정을 적용한 다음 NTDR로 저장하고 브라우저를 종료했다. 다른 프로필에서 그 파일을 직접 열어 두 레이어의 세 지점에서 저장 전과 같은 RGB를 확인했다.
- 세부 도구에서 설정값이 같은 프리셋 두 개를 번갈아 선택했을 때 누른 이름 하나만 강조됐다. 손떨림 보정값은 슬라이더를 잡은 상태에서 갱신됐다. 변형 수치를 편집한 채 도구를 누르면 입력 안내가 나타나고, Enter로 확인한 뒤에는 한 번 눌러 도구를 전환할 수 있었다.
- 채우기 속성에서 실제 레이어 이름과 참조 레이어 부재, 잠금, 숨김, 불투명도 0 안내를 각각 확인했다. 이미지와 마스크를 칠할 때는 현재 대상이 속성에 표시된다.
- Windows 임시 프로젝트에서 도킹 폭을 바꾸고 정상 종료한 뒤 새 프로세스를 띄웠다. 그림과 도킹 폭이 복원됐고, 내비게이터를 캔버스 왼쪽에 놓는 조작도 성공했다. 이 검사에서 발견한 한 프레임의 폭 되돌림은 편집기 승인이 올 때까지 마지막 폭을 유지하도록 수정했다. 최종 Windows 창에서 해당 한 프레임은 재측정하지 못했다.
- Windows에서 창을 커서가 있는 모니터로 옮기던 중 GPUI가 이미 사용 중인 앱 상태에 다시 접근해 종료되는 현상을 재현했다. 창을 만들기 전에 모니터를 지정하도록 고친 뒤 임시 프로젝트에서 편집기 시작과 정상 종료를 확인했다.
- Windows RTX 3080에서 DX12와 Vulkan 각각에 대해 화면이 숨겨진 상태의 캔버스 명령을 검사했다. 오래된 요청은 거부됐고, 유효한 요청은 편집 작업이 완료된 뒤 64×48로 반영됐다. 저장과 PNG 갱신을 마치고 별도 프로세스에서 NTDR을 다시 열어 64×48을 확인했다. 이 검사는 화면 표시와 펜 입력을 포함하지 않는다.

## Edge에서 재현한 동작

임시 브라우저 프로필과 새 그림을 사용했다. 레이어와 색상환은 1920×1080, 도킹은 1440×900에서 검사했다.

| 사용자 동작 | 관찰한 결과 | 수정 후 통과 기준 |
| --- | --- | --- |
| 두 레이어에 떨어진 위치에 각각 선을 그린다. 1번을 선택한 채 2번 행을 우클릭해 색 조정에서 밝기를 +70으로 미리본다. | 2번 메뉴를 열었는데 1번 선의 RGB가 (109, 69, 69)에서 (255, 247, 247)로 바뀌었다. 2번 선은 원래 색이었다. 기존의 색 보정은 작업 메뉴에서 현재 레이어를 대상으로 열렸다. | 행에서 시작한 보정은 해당 행을 명시적인 대상으로 삼는다. 취소·확정까지 같은 대상을 유지한다. |
| 세부 도구와 캔버스 사이의 경계를 오른쪽으로 125px 끌어 놓는다. | GPUI에서 캔버스 왼쪽 좌표가 281→407→281로 돌아가고 상태 변경 오류가 표시됐다. 기존판은 304→429로 바뀌어 재시작 후에도 429였다. | 놓은 위치가 유지되고 재시작 후 같은 폭으로 열린다. 드래그 도중 캔버스 크기 변경이 일어나도 마지막 동작이 유효해야 한다. |
| 내비게이터 제목을 다른 패널로 끌면서 작품을 본다. | 기존판은 그림을 유지했다. GPUI는 드래그 중 캔버스를 숨겼고, 놓으면 다시 표시했다. 패널 이동 자체는 성공했다. | 드롭 위치 표시와 작품을 동시에 볼 수 있다. |
| 창을 768×750으로 좁힌다. | GPUI의 기본 배치에서 왼쪽 도구 열은 약 22px, 속성·빠른 크기 열은 약 58px로 줄어 버튼이 잘렸다. 상단 바가 여러 줄이 돼 캔버스는 y=113에서 시작했다. 기존판은 왼쪽 속성 224px와 캔버스 y=61을 유지했으나 오른쪽 패널 일부가 잘렸다. | 필요한 도구를 알아보고 누를 수 있다. 양쪽 폭을 확보하기 어려우면 사용자가 패널을 접고 다시 열 수 있다. |
| 펜으로 작업하다가 색상환 가운데에서 색을 고르고 즉시 E를 누른다. | 기존판은 지우개가 선택됐다. GPUI는 펜에 머물렀다. 같은 GPUI에서 펜 버튼을 누른 직후 E를 누르면 지우개로 전환됐다. | 색을 선택하고 키 하나로 지우개로 바꿀 수 있다. 색상 축의 방향키 조작도 유지한다. |
| 그림 일부 또는 전체를 선택한 뒤 펜으로 작업한다. | 기존판은 캔버스 위에 ‘선택 영역 안에 그리는 중’과 변형·복사·해제를 표시했다. GPUI에는 이 줄이 없다. 선택과 단축키는 남아 있다. | 도구를 바꿔도 현재 선택을 확인하고 펜으로 바로 해제할 수 있다. 변형 중에는 같은 위치에서 적용·취소를 찾을 수 있다. |

레이어 대상은 [GPUI의 행 메뉴](../../crates/editor-gpui/src/panels/layers.rs), [웹 보정 시작](../../crates/web-core/src/color_adjustment.rs), [Windows 보정 시작](../../apps/desktop/src/native_canvas/color_adjustment.rs)에서 확인할 수 있다. 도킹은 [GPUI 분할 핸들](../../crates/editor-gpui/src/dock.rs)과 [웹 명령 수신](../../apps/web/src/adapter.rs), 색상환은 [축의 포커스 처리](../../crates/editor-gpui/src/color_wheel.rs)와 [편집기 단축키](../../crates/editor-gpui/src/lib.rs), 선택 도구는 [기존 캔버스 조작부](../../crates/editor-ui/src/selection_context.rs)가 비교 지점이다.

## 코드에서 찾은 후속 검증 항목

| 작업 | 사용성 차이 | 실제 조작으로 확인할 기준 |
| --- | --- | --- |
| 선택을 유지한 채 메뉴 닫기 | 편집기 루트가 Esc를 받으면 메뉴를 닫으면서 제스처 취소도 보낸다. Windows는 진행 중인 제스처가 없을 때 선택을 해제한다. 기존 메뉴는 Esc를 자체 소비했다. | 선택을 만든 뒤 메뉴를 열고 Esc를 한 번 누르면 메뉴만 닫힌다. |
| Windows에서 캔버스 크기 변경·크롭 | 대화상자를 열 때의 문서 리비전으로 명령을 보내며, 작업 큐 접수 직후 대화상자를 닫는다. 처리 스레드가 나중에 명령을 거부하면 초안이 이미 사라져 있다. | 실제 적용을 확인하고 닫는다. 거부되면 입력값과 원인을 대화상자에 남긴다. |
| Godot용 PNG 저장 확인 | Windows 편집 중 현재 파일명·미저장 표시와 PNG 내보내기 진행·재시도 표시가 사라졌다. 종료 시 오류 안내는 남아 있다. 웹 단독판도 자동 복구 대기·저장 중·완료를 알리던 작은 상태 표시가 빠졌다. | 현재 문서, 프로젝트 저장, PNG 갱신을 구별할 수 있다. 웹 자동 복구는 작은 상태 표시로 확인할 수 있다. |
| 변형에서 바로 그리기 | GPUI 도구 레일은 변형 미리보기 중 모든 도구 아이콘을 비활성화한다. 기존 웹 경로는 입력값이 정리됐으면 도구를 눌러 변형을 마치고 그리기로 돌아갈 수 있었다. | 적용 가능한 상태에서 도구 전환 한 번으로 돌아간다. 미확인 수치가 있을 때는 그 이유를 표시한다. |
| 색 보정값 탐색 | 기존의 드래그 슬라이더·수치·초기화가 왼쪽 속성의 개별 텍스트 입력과 Enter로 바뀌었다. | 그림을 보며 펜으로 밝기·채도 등을 연속 조절하고 값을 초기화할 수 있다. |
| 채우기 대상 확인 | 속성에서 실제 대상 이름, 마스크 전환, 잠금·숨김·불투명도 0·참조 부재 안내가 빠졌다. 마스크 선택 시 속성에는 선택 영역 채우기만 남는다. | 어디에 칠하는지, 눌러도 변화가 없는 이유와 이미지·마스크 전환 방법이 해당 위치에서 보인다. |
| 크기를 지정해 PNG 내보내기 | 기존의 비율·가로·세로 직접 입력 중 가로 입력과 고정 배율만 남았다. 3×8 작품에서 높이 4로 지정해 2×4를 만드는 경로가 사라졌다. | 가로와 세로 어느 쪽을 기준으로 삼아도 반올림된 다른 축과 최종 치수를 확인할 수 있다. |
| 같은 설정의 프리셋 고르기 | 기존은 클릭한 이름 하나를 강조했다. GPUI는 값이 일치하는 모든 저장 프리셋을 선택된 것처럼 표시할 수 있다. | 동일한 값의 프리셋 두 개를 만든 후 하나를 누르면 누른 항목을 구별할 수 있다. |
| 손떨림 슬라이더로 수치 맞추기 | GPUI는 손잡이를 놓을 때 값을 전송해 드래그 중 옆 숫자가 따라오지 않는다. | 손을 떼기 전에 목표 수치에 맞출 수 있다. |
| 오래 고정해 둔 최근색 해제 | GPUI는 핀과 최근 사용 이력을 다시 조합한다. 사용 이력에서 밀린 색은 고정을 풀자마자 사라진다. | 고정을 푼 색은 일반 최근색으로 남고, 이후 다른 색을 실제 사용함에 따라 밀린다. |
| 애니메이션 프레임 넘기기 | 기존 프레임 목록은 좌우 방향키와 Home/End로 앞뒤·처음·끝 프레임을 선택하고 스크롤을 따라갔다. GPUI의 프레임 버튼에는 이 키 처리 경로가 없다. ‘앞으로·뒤로’ 버튼은 프레임 순서를 바꾸는 동작이다. | 프레임을 확인하려고 키를 연타해도 순서와 작품 데이터가 바뀌지 않고 현재 프레임이 보인다. |
| 참조 이미지에서 색 채취 | 기존은 패널의 가용 높이를 활용하고 누르고 있는 동안 후보 색을 색 견본으로 보여줬다. GPUI의 이미지 영역은 높이 170px로 고정되고 채취 미리보기는 HEX 텍스트만 남았다. | 패널을 키운 만큼 그림이 커지고, 놓기 전에 실제 색을 눈으로 확인할 수 있다. |

캔버스 적용은 [기존 처리](../../crates/editor-ui/src/page_panel.rs)와 [GPUI 처리](../../crates/editor-gpui/src/canvas_dialog.rs), 상태 표시는 [기존 상단 바](../../crates/editor-ui/src/chrome.rs), [Windows 호스트](../../apps/desktop/src/gpui_host.rs), [웹 호스트 표시](../../apps/gpui-web/src/platform.js)를 비교했다. 브러시·채우기·색 보정은 [공유 도구 패널](../../crates/editor-gpui/src/panels/artwork.rs), [기존 채우기](../../crates/editor-ui/src/fill_panel.rs), [기존 색 보정](../../crates/editor-ui/src/color_adjustment_dialog.rs)이 기준이다.

브러시 크기의 기본 12칸과 최근 4칸, 크기·불투명도 직접 입력, 접힌 필압 옵션은 전환 시 유지됐다. 내비게이터의 중심 이동·확대·맞춤, 히스토리의 실행 취소·다시 실행·분기, 참조 이미지의 열기·이동·확대·색 채취 경로도 코드 대조에서 확인했다. iPad와 물리 펜 조작은 별도 검증 대상이다.
