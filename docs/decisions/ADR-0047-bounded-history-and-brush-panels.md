# ADR-0047: 128단계 히스토리 우회와 왼쪽 도구 창 분리

## 결정

무제한 히스토리의 지연 로딩 설계는 보류하고, 현재 편집기의 히스토리
노드 총수를 최대 128개로 제한한다. UI 목록만 자르는 변경이 아니다.

- 현재 위치로 이어지는 Undo 경로를 우선 보존한다. 선형 작업에서는
  최근 128단계까지 Undo할 수 있다. Undo/Redo 자체는 기록 수를 늘리지 않는다.
- 다른 분기도 남은 슬롯 안에서만 보존한다. 연결된 부모를 먼저 유지하고
  형제 중 큰 ID를 우선한다. 모든 분기의 무한 보존은 더 이상 보장하지 않는다.
- 경로가 128개를 넘으면 잘린 마지막 상태를 새 보관 시작점으로 삼는다.
  시작점의 정확한 픽셀 root, 레이어 계층, 페이지 크기를 유지한다.
- 새 작업의 기록/스냅샷/커서 갱신과 오래된 기록 정리는 같은 redb
  트랜잭션에서 커밋한다. 메모리 세션도 같은 정책을 적용한다.
- 이전 형식의 유효한 프로젝트도 열 때 검증 후 128개로 정리한다.
  잘린 히스토리는 앱에서 복원할 수 없다. 중요한 옛 기록은 구버전 파일 사본으로 보존한다.
  비어 있지 않은 잘못된 프로젝트는 정리 전에 거부하고 원본을 유지한다.

## 명시적인 한계

ROOTS/OBJECTS의 미사용 픽셀 blob 회수나 DB compaction은 이번에 하지 않는다.
따라서 기존 파일은 즉시 작아지지 않고, 앞으로도 고유 타일 데이터로 인해
용량이 증가할 수 있다. 메모리/재열기용 히스토리 그래프를 제한한 우회이지,
파일 크기 상한 또는 장시간 드로잉 성능 보장은 아니다.
이전 파일 검증의 100,000 노드 방어 상한도 남아 있다.
향후 디스크 지연 로딩과 안전한 참조 기반 공간 회수를 별도 설계한다.

## 왼쪽 UI

기존 `Brush` 하나 안의 세 영역을 실제 독립 도킹 패널로 분리한다.

1. 세부 도구 (`Brush`): 세부 도구 선택.
2. 도구 속성 (`ToolProperties`): 현재 도구 설정. 변형/페이지 설정도 이 창에 표시.
3. 크기 빠른 선택 (`BrushSizes`): 최근 크기 최대 4개와 수치별 빠른 선택 목록.

각 창은 자체 도킹 핸들/높이 조절을 갖고, 최하단 창이 남는 높이를 채운다.
기존 NYDOCK01/02 배치는 Brush 위치만 세 창 스택으로 확장한다.
NYDOCK03/NYHIGH02에 새 패널 ID를 기존 ID 뒤에 추가한다.
이전 통합 Brush 높이는 새 세부 도구 높이로 재사용하지 않는다.

크기는 0.1–200 px, 불투명도는 1–100%를 숫자로 표시/입력한다.
숫자 입력 중에는 도구 전환 단축키가 실행되지 않는다.
값 확정 시 기존 EditorCommand를 사용하며 raw input 경로는 변경하지 않는다.

## 목업 단축키 복원

WebView UI와 네이티브 캔버스 양쪽 입력 경로를 동일하게 맞춘다.

| 키 | 반복 입력 시 순서 |
|---|---|
| g | 이동 → 마법봉 → 올가미 |
| b | 연필 → 펜 → 브러시 |
| e | 지우개 |
| f | 채우기 → 그라데이션 |

그룹 밖에서 누르면 첫 도구로 진입한다. 기존 w/l/Shift+f 개별 지정은 제거한다.

## 검증

- 코어 회귀: 132개 작업 후 별도 프로세스로 재열기, 정확한 128회 Undo/Redo.
  signed/off-page 픽셀, 레이어 이름, 페이지 크기를 매 단계 비교.
- 129번째 작업 커밋 직전 실패 시 기존 128개 기록과 시작점 유지.
- 제한 경계에서 Undo 후 새 stroke 분기 생성 및 재열기 일치.
- 관련 코어/데스크톱 테스트와 Clippy 통과. UI는 별도 실제 Release 실행으로 확인한다.
- Windows Release 실행에서 기존 배치 사본이 세 창으로 전환됨을 확인했다.
  크기 12.5 px/불투명도 37% 입력 후 Tab 확정, 최근 크기/슬라이더 반영 확인.
  UI 키 입력으로 g 이동→마법봉→올가미 및 f 채우기→그라데이션 확인.
  세부 도구 높이 +38 px 조절 후 정상 종료/재실행에서도 높이가 유지됐다.
  테스트 전용 빈 프로젝트를 사용했고 기존 사용자 작품은 열거나 수정하지 않았다.
- 플랫폼 검증은 Windows 범위. 실물 펜/장시간 지연 측정은 이번 증거에 포함하지 않는다.
