# ADR-0064: 공용 편집 실행과 웹 호스트 연결

상태: 로컬 구현·핵심/브라우저 검증. 공개 배포·설치 갱신은 별도.

## 문제

공용 Dioxus UI와 브러시를 사용해도 웹 호스트가 선택·변형·레이어 명령을 받지 않으면
기능은 동작하지 않는다. 데스크톱 worker의 로직을 웹에 복사하면 이후 수정이 갈라진다.

## 결정

`crates/editor`에 기존 데스크톱의 다음 로직을 옮기고 양쪽에서 직접 호출한다.

| 공용 코드 | 책임 |
|---|---|
| `gesture` | 사각형·올가미·마법봉·채우기·그라데이션 입력을 편집 명령으로 변환 |
| `layer_edit` | 계층·잠금·복제·순서·합성 속성 검증과 변경 계획 |
| `pixel_edit` | 선택/픽셀/페이지 연산과 스포이트 채취, OS 없는 클립보드 계약 |
| `transform` | 고정 원본, 미리보기 세대, 확정·취소, 임시 붙여넣기 |
| `transform_gesture` | 변형 핸들 판정과 이동·크기·회전 계산 |

픽셀 알고리즘은 기존 `paint-cpu`, 문서는 `document`/`tiles`를 그대로 쓴다.
DB나 GPU를 공용 편집 연산의 권위 상태로 삼지 않는다.

- Windows는 writer의 DB commit 성공 뒤 공용 결과를 수용한다. GPU-first 획 경로는 유지한다.
- 웹은 자원 한도를 확인하고 세션 이력에 수용한 뒤 저장 Worker로 변경을 보낸다.
  CPU 브러시/편집과 WebGPU 표시는 메인 WASM에, NTDR 압축·IndexedDB는 Worker에 남는다.
- `TransformStore`가 snapshot/타일 읽기, preview 검증, 최종 commit의 호스트 경계다.
  미확정 타일·임시 레이어는 표시만 하며 자동 저장 snapshot에 들어가지 않는다.
  오래된 세대의 commit이나 한도를 넘는 preview는 수용하지 않는다.
- 도구 전환 판정도 공용이다. 유효한 변형/붙여넣기는 확정하며, 변경 없는 원본 변형만
  취소한다. 실패한 preview 뒤에는 마지막 표시 결과를 재검증하고, 실패하면 도구/초안을 유지한다.
- 웹 클립보드는 세션 메모리, Windows는 기존 시스템 이미지 클립보드다.
  클립보드 접근과 commit 실패가 기존 그림을 일부만 수정하지 않도록 후보 상태를 사용한다.

웹은 그룹을 포함한 최대 32개 노드, 1024개 resident tile, 한 변 4096px의 기존 예산을
적용한다. 그룹 지원을 위해 예산을 무제한으로 풀지 않는다. 입력 좌표도 유한하다.
NTDR 포맷은 같으며 별도 웹 편집 파일 형식을 추가하지 않는다.

## UI 수명과 표시

스포이트의 13×13 픽셀 미리보기·후보 RGB·버블 마크업을 `editor-ui::picker_loupe`로 공유한다.
Windows의 비동기 읽기 actor는 그대로 두고 웹은 최신 이동을 제한 주기로 샘플링한다.
확대 버블은 읽기 전용이고 색상 채택은 release에서만 한다.

도킹 UI도 같은 소스다. 웹 GPU가 연결된 HTML canvas는 Dioxus 패널의 자식 수명과 분리하고
도킹으로 슬롯이 바뀌면 같은 객체를 새 슬롯에 붙인다. 옮기는 동안 진행 중 제스처는 취소한다.
도킹 직렬화는 `editor-ui::layout_codec`로 공유하며 네이티브 파일/브라우저 설정 저장만 다르다.

## 데스크톱의 저장 위치 없는 새 그림

버거메뉴의 **새 그림**은 저장 대화상자를 띄우지 않는다.
`%LOCALAPPDATA%/NyatiDraw/Sketchbook/새 그림 N.ntdr`을 `create_new`로 예약하고
기존 프로젝트 전환/저장 마무리 경로로 연다. 투명 래스터 한 장으로 시작한다.
사용자가 경로를 고르지 않는다는 의미이지 자동 복구를 끄는 의미가 아니다.
원하면 **다른 이름으로 저장**으로 작업 폴더를 지정한다.

이미 있는 프로젝트와 같은 이름의 PNG도 피하며, 빈 복구 파일 예약 실패 시 현재 그림은 유지한다.
저장/종료가 진행 중이면 새 그림 요청을 거절한다. 설치본은 자동으로 교체하지 않는다.

정상적으로 열린 프로젝트 경로는 기존 writer에서 별도 `workspace.recent`에 기록한다.
최대 20개이며 lossless UTF-16 경로, 길이 제한, 임시 파일 교체를 사용한다. 입력 hot path나
프로젝트 이력에는 목록 기록을 넣지 않는다. UI는 캐시만 읽는다. 손상된 목록은 보존한다.
인자 없는 실행은 존재하는 최근 그림을 우선하며, 버거메뉴에 최근 그림 선택을 제공한다.
설정 경로 override는 Sketchbook도 격리한다. 자세한 [보관 의미론](../sprints/current-priorities.md)을 따른다.

## 검증과 남은 차이

[웹 지원 문서](../web-support.md#공용-편집-기능-확장-로컬-검증)에 실행 근거를 기록한다.
핵심 검사에는 원본 보존, 미확정 편집/취소, 선택 밖 픽셀 보존, 그룹과 타일의
별도 네이티브 프로세스 재열기가 포함된다. 새 그림의 이름 충돌 보존도 검사했다.
사용자 설치 앱은 교체하지 않았다. 격리 debug/release의 WebView 메뉴에서 새 그림·최근 파일
전환·즉시 목록 갱신·Save/PNG export를 확인했다. OS 종료 버튼/실제 펜/네이티브 화면 캡처와
새 그림 자체의 마지막 프로세스 재열기는 미확인이다. [최신 검증 경계](../sprints/current-priorities.md) 참고.

웹의 OS 클립보드 교환, 데스크톱 이력 분기 탐색, 파일 연결/동일 경로 덮어쓰기는 별도다.
반복·메시 변형·레이어 색상화처럼 양쪽 모두 준비 중인 기능을 이번 연결 작업으로
완료했다고 간주하지 않는다. 물리 펜/고주사율/대형 작품 성능 동등성도 주장하지 않는다.

새 외부 의존성은 없다. 내부 workspace `nyatidraw-editor`/`nyatidraw-paint-cpu` 0.1.0을
재연결했으며 Dioxus 0.7.9와 기존 lockfile의 외부 버전은 유지한다.
