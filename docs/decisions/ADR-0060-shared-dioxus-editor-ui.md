# ADR-0060: 데스크톱 기준 공용 Dioxus 편집 화면

## 결정

웹 지원은 별도 축소 디자인을 만드는 작업이 아니다. 사용자가 다듬은 데스크톱 화면을
기준으로 레이아웃·패널·아이콘·스타일·UI 동작을 최대한 그대로 공유한다.
ADR-0059의 별도 웹 런타임과 저장 제한은 유지하지만, 별도 웹 화면 구현은 폐기한다.

`crates/editor-ui`가 편집 화면의 단일 원본이다. Dioxus Desktop과 Dioxus Web이 모두
같은 `EditorChrome`을 렌더링한다. Dioxus Native로 돌아가지 않는다.

## 경계

| 공유하는 부분 | 호스트에 남기는 부분 |
|---|---|
| 상단 명령, 도구/세부도구, 속성, 크기 빠른 선택 | 파일 선택·다운로드·업데이트 |
| 도킹 트리 렌더링, 드래그, 너비·높이 조절 | OS 설정 파일 또는 브라우저 설정 저장 |
| 내비게이터, 색상환, 최근/고정 색, 레이어, 히스토리 | 미리보기 데이터 공급과 실제 문서 명령 실행 |
| 캔버스 설정 창, 변형 속성, 단축키 | 네이티브 캔버스 HWND 또는 WebGPU canvas |
| CSS, SVG 아이콘, 색상환·도킹의 DOM 상호작용 | 저장·복구·종료, 플랫폼 입력 |

`UiBackend`는 `UiProjection`, `EditorCommand`, 읽기 전용 미리보기와 사용자 설정만
주고받는다. 원시 펜 샘플·GPU 장치·DB·파일 경로를 UI 명령에 넣지 않는다.
`UiSlots`로 플랫폼 캔버스, 파일 버튼, 업데이트 제어를 주입한다.

공용 UI는 Win32, Dioxus Desktop, 파일 시스템, 스레드에 의존하지 않는다.
입력은 기존 호스트 경로를 유지한다. 브라우저의 CPU 브러시와 데스크톱의 GPU-first
경로를 같은 것으로 표시하지 않는다.

## 미지원 기능

브라우저의 기능 부족을 이유로 도구 분류나 배치를 새로 만들지 않는다.
동일한 위치에서 지원 여부를 구분하고, 미지원 명령은 비활성화하거나 명시적으로
거부한다. 활성 버튼이 아무 일도 하지 않거나 다른 기능을 대신 실행하면 안 된다.
외형 공유는 `.ntdr` 호환이나 Windows 기능 전체 이식의 완료 판정이 아니다.

## 검증

기존 Dioxus/Dioxus Desktop/Dioxus Web/DX `0.7.9`를 유지하며 새 프레임워크는 추가하지
않았다. 공용 crate는 Dioxus의 `lib` 기능만 선택하고 호스트가 renderer를 선택한다.

Windows all-target Clippy, WASM Clippy, 양쪽 DX release 빌드와 기존 핵심 테스트 8개가
통과했다. 로컬 브라우저에서 공유 배치·도구·수치 입력·색상환·불투명도 드래그·패널
너비/높이·탭·메뉴·캔버스 프리셋을 확인했다. 탭 재개 후 두 레이어/불투명도 53%/
2B 16px를 복구했고 내비게이터·레이어 미리보기 PNG 데이터가 일치했다. 재개 후
펜→연필 전환에서도 2B/16px가 유지됐다. 관찰 중 브라우저 경고·오류는 없었다.

UI 단위 테스트는 추가하지 않았다. 미리보기 일치는 전체 원본 픽셀의 동일성 증명이
아니며, 탭 재개는 전체 프로세스 재시작 증거가 아니다. 실제 Windows 창과 물리 펜의
이번 UI 통합 회귀 검증은 남아 있다. 상세 범위는 [웹 지원](../web-support.md)에 기록한다.

이번 변경은 아직 공개 배포하지 않았다. 데스크톱 설치본과 사용자의 작품 파일은
교체하거나 수정하지 않았다.
