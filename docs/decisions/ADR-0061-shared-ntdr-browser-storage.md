# ADR-0061: 브라우저와 데스크톱의 NTDR 저장 형식 공유

## 결정

웹도 `.ntdr`를 읽고 쓴다. ADR-0059의 별도 웹 저장 형식을 폐기하고 기존 파일의
읽기 마이그레이션만 유지한다. 이름만 같은 형식이나 평면 이미지 변환 파일을 만들지 않는다.

- `project`: 기존 버전 레코드, 타일 zstd 코덱, 공용 `NYTOOL01` 도구 설정.
- `project-redb`: 기존 redb `4.2.0` 파일과 트랜잭션. 네이티브는 파일 백엔드,
  브라우저는 용량 제한을 가진 메모리 `StorageBackend`를 사용한다.
- `project-web`: 웹 문서와 저장 세션의 어댑터. 들어온 DB의 기록·메타데이터를
  유지하고, 수정 결과를 공용 structural change로 저장한다.
- 브라우저 호스트: 완전히 닫힌 DB 바이트를 IndexedDB에 저장하거나 내려받는다.

`web-core`에는 DB·파일·DOM 의존성을 넣지 않는다. zstd `0.14.0`의 기존
WASM 지원을 사용하며 전용 이미지 코덱이나 새로운 DB를 추가하지 않는다.
WASM C 빌드에 LLVM Clang이 필요하다.

## 보존과 실패 경계

가져오기·저장은 성공한 결과만 현재 작업/수락한 파일 바이트로 채택한다.
signed 좌표와 페이지 밖 픽셀, 레이어 ID·속성·순서, 기존 히스토리를 보존한다.
지원하지 않는 그룹과 자원 한도 초과는 명시적으로 거부하며 임의 평탄화하지 않는다.
알 수 없는 도구 설정은 원본을 유지하거나 오류를 알리고, 기본 설정으로 조용히 덮지 않는다.

NTDR 저장소는 128MiB로 제한하며 파일 크기 제한과 압축 해제 후 작업량 제한은 별개다.
현재 웹 픽셀 상한은 1024타일, 레이어 32개, 페이지 축당 4096px이다.
메모리 커밋만으로 저장 완료라고 표시하지 않고 IndexedDB 쓰기 완료를 기다린다.
진행 중인 획은 저장하지 않는다.

기존 IndexedDB 이름과 `current` 키를 유지한다. `NYWEB001` 복구 데이터를
처음 NTDR로 저장할 때 기존 바이트는 `legacy-before-ntdr`에 같은 트랜잭션으로 남긴다.
손상된 복구 데이터를 새 빈 파일로 덮어쓰지 않는다.

## 범위

같은 파일 형식은 같은 기능 지원을 뜻하지 않는다. 웹의 세션 Undo UI, 그룹 편집,
선택/변형/반복 등 아직 연결되지 않은 기능은 별도 작업이다.
사용자 작품·설치본·현재 드로잉 탭은 검증 대상으로 사용하지 않는다.

검증은 핵심 포맷 왕복/실패 보존 테스트, 양쪽 컴파일, 실제 브라우저에서 NTDR
열기·저장·재개, 네이티브 재열기로 나눈다. 실제 펜·전체 프로세스 재시작·성능 동등성은
이 포맷 변경만으로 검증한 것으로 기록하지 않는다.
