# 큰 그림 축소 표시 품질

## 범위

웹과 Windows가 공유하는 `nyatidraw-paint-gpu`의 캔버스 표시를 수정한다.
원본 CPU/GPU level 0 픽셀, 브러시, Undo, 프로젝트 포맷, PNG 출력은 바꾸지 않는다.
내비게이터·레이어의 CPU 썸네일이나 선택 변형으로 픽셀 자체를 줄이는 알고리즘은 별도 경로다.

## 수정 전 재현

RTX 3080, Windows 10.0.26200, Vulkan, release profile에서 합성 패턴을 실제 GPU에 렌더한 뒤 읽었다.
`gpu_viewport_minification` 예제로 1025×769 페이지와 음수 좌표 바깥 타일에 1픽셀 체크,
가는 선, 작은 명암 질감을 넣었다. 25%·12.5%·19%, 분수 이동·회전, 타일 경계를 검사했다.

| 패턴 | 조건 수 | 평균 명암 오차 범위 | 최대 명암 오차 |
|---|---:|---:|---:|
| 1픽셀 체크 | 8 | 127.5 | 127.5 |
| 4픽셀 간격 가는 선 | 8 | 63.75–191.25 | 191.25 |
| 작은 명암 질감 | 8 | 18–90 | 90 |

명암 오차는 premultiplied linear RGBA8 기준의 알려진 면적 평균과 비교한 0–255 값이다.
24개 조건 모두 기존 Nearest / LOD 0 표시에서 실패했다. 원본 타일은 바뀌지 않았다.

공개 alpha.18을 격리 Edge에서 열어 4095×2305 합성 PNG를 화면 맞춤(약 22%)으로 표시했다.
체크·가는 선·동심원에 모아레와 선 누락을 관찰했다. 사용자 작품은 사용하지 않았다.
PNG 복사로 얻은 원본 출력의 디코딩 RGBA SHA-256은 다음과 같다.

`0f8e57e719de8053469a27170eb3e5a5112e8d020884e23093446294f1bce9b9`

## 표시 방식

- 최종 레이어 합성 결과에만 축소용 mip 단계를 만든다. 레이어별로 먼저 줄여 합성하지 않는다.
- premultiplied linear RGBA 네 채널을 함께 면적 평균한다. 홀수 크기의 가장자리도 가중치에 포함한다.
- 실제 화면 픽셀보다 원본 픽셀이 큰 1:1·확대에서는 기존 픽셀 표시를 유지한다.
  축소에서는 배율에 맞는 mip와 선형/LOD 보간을 사용한다.
- 페이지 root를 먼저 최신화해 비가시 영역의 오래된 픽셀이 축소에 섞이지 않게 한다.
  변경이 없는 root의 mip를 매 프레임 재생성하지 않는다.
- 페이지 밖 타일은 투명 경계 필터의 기여분을 half-float 누적면에 더한 후 한 번 합성한다.
  인접 타일을 개별 clamp 처리해 이음새를 만들지 않으며 화면 밖 필터 범위도 포함한다.

## 메모리와 호환성

기존 base scene 512 MiB 제한과 sparse atlas 슬롯 계산을 유지한다. 표시용 mip는 실제 크기를
합산해 별도 256 MiB 상한을 적용한다. 길쭉한 `1×N` 텍스처의 mip 합은 원본의 1/3보다
클 수 있으므로 일괄 1/3로 계산하지 않는다. Root의 추가 mip는 root 원본보다 작고, base
예산에는 root와 같은 크기의 stroke backup도 있다. Atlas 추가 mip는 atlas base의 1/3보다
작아 기존 base 예산 안에 들어온 장면은 이 별도 mip 상한 때문에 거절되지 않는다.

페이지 밖 그림의 누적면은 필요할 때만 실제 화면 크기로 할당하며 resize 시 폐기한다.
비용은 물리 화면 픽셀당 8바이트이며 프로젝트 예산과 별도다. 기존 화면 텍스처에도
독립된 바이트 예산은 없었으므로 이를 전체 GPU 메모리 512 MiB 보장으로 해석하지 않는다.

## 검증 경계

실제 GPU 읽기값과 브라우저 화면은 각각 확인한다. 합성 입력을 물리 펜·고주사율·입력 지연
검증으로 해석하지 않는다. 이 기록은 품질 검사이며 p50/p95/p99 성능 수치는 측정하지 않는다.
스크래치 로그·이미지는 ignored `output/playwright/minification-*`에 둔다.

실행: `cargo run -p nyatidraw-paint-gpu --example gpu_viewport_minification --release --locked`.

## 수정 후 검증

24개 축소 조건이 모두 통과했다. 최대 명암 오차는 체크 0.5, 가는 선 0.25, 질감 1이었다.
원본 타일 byte-exact, 1:1·3배 확대 픽셀 정확성, 화면 밖 수정 후 축소·이동 시 갱신,
반투명 경계, 홀수 페이지 마지막 행·열·모서리 검사도 통과했다.

기존 `gpu_layer_viewport` release 예제의 그룹 합성·가시성·순서·불투명도,
affine/HiDPI·보기 반전·중첩 solo·트리 삭제 복원·할당 거부 검사도 통과했다.
workspace 전체 핵심 테스트, 전체 타깃 Clippy, WASM UI/Worker Clippy,
fmt 검사와 웹·Windows release 빌드가 성공했다. 테스트 집계의 자식 프로세스 검증은
별도의 고유 테스트 개수로 부풀리지 않는다.

격리 Edge에서 같은 4095×2305 PNG를 22%로 표시했다. 체크·가는 선·질감은 평균 명암으로
안정되었고 동심원은 끊김과 모아레가 줄었다. 축소 상태에서 획 입력·Undo·17도 보기 회전을
확인했다. PNG 복사의 디코딩 픽셀 해시는 수정 전과 일치했고, Undo·회전 후 및 브라우저
프로세스를 닫아 다시 열어 자동 복구한 후에도 위 SHA-256과 같았다.

`output/playwright/minification-before-ui.png`, `minification-after-ui.png`,
`minification-after-stroke.png`, `minification-after-rotated.png`에 로컬 화면 증거를 남겼다.
로컬 favicon 404와 WebGPU adapter 선호도 경고 외 앱·셰이더 오류는 관찰하지 않았다.
Windows 설치본은 교체하거나 실행하지 않았다. 공개 배포 결과는 완료 후 별도로 기록한다.
