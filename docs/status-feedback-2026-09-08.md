# 다음 버전 전 사용자 피드백 반영

## 구현

- 상단 캔버스 작업 툴바에 `비우기`를 연결했다. 현재 래스터 레이어의 페이지 밖을
  포함한 모든 픽셀을 지우되 레이어 ID/속성과 다른 레이어는 유지한다. 선택 영역과
  무관하며 잠긴 레이어는 거절한다. 기존 writer의 structural history commit을
  사용해 Undo/Redo 및 저장 후 재열기를 지원한다. 빈 레이어에는 히스토리를 추가하지 않는다.
- 기본 오른쪽 도킹 비중을 14%에서 18%로 늘렸다(캔버스와 오른쪽 패널의 분할 기준).
  기존 좁은 레이아웃에도 레이어 이름 공간을 확보하도록 레이어 패널 최소 너비는
  280px로 지정했다. Solo와 큰 미리보기는 유지한다.
- 레이어 추가 버튼은 `+` 아이콘을 사용한다. 브러시 시작 크기는 5px,
  시작 불투명도는 100%로 UI projection과 실제 브러시 초기값을 맞췄다.
  도구별 마지막 크기 복원은 아직 미구현이며 현재 크기는 도구 간 공유한다.
  기존 작품의 레이어 불투명도와 저장된 획/preset은 변경하지 않는다.
- 새 문서는 `Layer 1` 투명 래스터 한 장으로 시작한다. 초기 트리를 첫 획 전에
  저장해 빈 상태로 Undo하거나 프로세스를 다시 열어도 기준이 바뀌지 않는다.
- 기존 문서의 저장된 트리는 유지한다. 레이어 메타데이터가 없던 옛 문서와 옛
  history cursor만 과거 기본 트리로 해석해 레이어 2의 기존 픽셀을 숨기지 않는다.
  합성 입력/프로토콜 검사의 다중 레이어 fixture는 새 문서 기본값과 분리했다.
- 흰 배경 추가는 고유 ID의 **일반 래스터**를 맨 아래에 생성한다. 예약 ID나
  특수 배경 레이어를 사용하지 않고 활성 그리기 레이어도 바꾸지 않는다.
  문서 가장자리 타일의 페이지 밖 픽셀은 투명하게 남긴다.
- 가로 도킹 경계에 6px 너비 조절 핸들을 추가했다. 드래그 중 안내선만 표시하고,
  놓을 때 한 번 기존 Dock Replace 명령으로 저장한다. 최소 너비, 키보드 조절,
  Escape/캡처 손실/포커스 이탈/오래된 revision 취소와 캔버스 좌표 갱신을 연결했다.
- 무채색 N/연필 로고를 추가했다. `apps/desktop/assets/nyatidraw.svg`가 편집 원본이며
  `python tools/build-logo.py`가 PNG/다중 해상도 ICO/64px RGBA를 만든다(Pillow 필요).
  일반 빌드에는 Python이 필요 없다. DX 실행파일 리소스, 창 아이콘, 설치 패키지에 연결했다.
- 설치 제품 ID/표시명은 NyatiDraw, 배포 실행파일은 `nyatidraw.exe`로 통일했다.
  기존 Alpha 설치는 건드리지 않는다. 구 updater의 제품 ID 검증 부재 때문에
  새 제품은 `nyatidraw-alpha` 피드로 분리하며 새 updater는 제품 ID를 검증한다.
  자세한 배포 절차는 [releasing.md](releasing.md)를 따른다.
- 동일 immutable tile/root envelope의 반복 DB insert를 생략한다.

## 초기 피드백 빌드 검증과 한계

- Desktop 핵심 테스트 **27 통과 / 명시적 registry acceptance 1개 미실행**.
  새 문서 그림은 별도 테스트 자식 프로세스에서 재열어 픽셀 root와 초기 트리가
  같음을 확인했다. 흰 래스터의 비예약 ID 및 1×1/128×128/129×257 페이지 경계 검사를 통과했다.
- project-redb **15개 통과**, 해당 저장소의 별도 프로세스 crash/reopen probe 통과.
- workspace all-target/all-feature Clippy, rustfmt 및 DX Windows Release 빌드 통과.
  vendored Wry/Dioxus의 기존 경고는 남아 있다.
- 빌드 SHA256: `195e04fb3a7a935792a24a8f1ca4225953b099c01a7c15e74e66a1221859006d`.
- computer-use로 작업 폴더의 새 실행파일을 관찰했다. 창 아이콘과 단일 투명 레이어,
  렌더링을 확인했다. 임시 프로젝트와 별도 layout 경로를 사용했다.
  첫 드래그 도구 호출은 screenshot ID 오류, 재선택 뒤에는 사용자 입력 감지로
  조작을 중단했다. 실제 사이드바 드래그/캡처 취소/재시작 후 너비 복원은 미검증이다.
  사용자 입력이 있는 검증 창과 임시 그림은 닫거나 삭제하지 않았다.
- 새 ID 설치 프로그램 생성·설치·업데이트·파일 연결의 실제 OS 수용은 미실행이다.
  기존 설치본 갱신, Git commit/push, 태그, 릴리스 공개는 하지 않았다.

## 출하 전 남은 일

1. **NTDR 용량 문제는 아직 해결되지 않았다.** 작은 before/after fixture의 파일 크기는
   양쪽 모두 같았다. 이번 변경을 압축이나 파일 축소로 설명하면 안 된다.
   [측정 및 압축 검토](measurements/immutable-record-writes-2026-09-08.md)에 raw tile,
   history/manifest 비용, LZ4 후보와 구버전 읽기 호환성 문제를 정리했다.
   다음 단계는 대표 프로젝트의 테이블별 용량 측정과 schema-gated 압축이다.
2. 사이드바 실제 입력 수용 및 새 제품 설치 수용. 패널 7개와 툴바를 전부 가로로
   도킹한 극단 배치는 최소 너비 합이 1260px이므로 더 작은 창에서 잘릴 수 있다.
3. 기존 간헐적 빈 창 시작 문제는 별도 관찰이 필요하다. 아래 후속 변경은
   마우스 캡처와 입력 종료를 보완하지만 물리 펜/캡처 취소의 모든 OS 경로를
   검증한 것은 아니다.
4. 브러시 크기 직접 입력은 사용자 지시로 보류한다.

위 항목을 확인하기 전에는 다음 릴리스 태그를 생성하지 않는다.

## 후속: Windows 캔버스 합성, 팬 이동, 위젯 높이

- 네이티브 상대 팬 명령은 최신 UI projection이 도착하기를 기다리지 않는다.
  기존 bounded FIFO 안에서 인접 델타만 합치며, 일반 UI 명령의 revision 검사와
  확대/축소 등의 순서는 유지한다. fractional DPI/휠 잔여값도 보존한다.
- 마우스 획 Begin에서 캡처하고 End/Cancel에서 자기 캡처만 해제한다.
  캡처 손실은 Cancel로 처리하며, 캡처 API의 동기 재진입 전에 상태 접근을 끝낸다.
- 세로 패널 경계도 6px 핸들로 조절한다. 드래그 동안 안내선, 놓을 때 적용한다.
  앞 패널은 고정 높이, 마지막 패널은 남은 공간을 채운다. 28-byte versioned
  `workspace.heights`를 기존 설정 writer에서 비동기로 저장한다.
- Windows의 WebView2/DirectComposition 어댑터와 OS 타입 없는 `HostLayout`을
  분리했다. Linux/macOS는 같은 입력 소유권·합성·수명 계약을 구현할 후속 대상이지,
  현재 Windows 구현이 그대로 이식되거나 이미 검증됐다는 뜻이 아니다.
- 종료 실패를 확인하고 종료할 때 이미 닫은 엔진을 다시 닫아 Failed 상태를
  되살리던 경로를 수정했다. 정상 surface retirement 뒤 HWND를 파괴한다.

검증용 scratch 프로젝트에서 마우스 획을 저장하고 프로세스를 재시작해 같은
root와 7개 타일을 재열었다. 이동 도구 드래그 260×120px가 같은 팬 명령 경로로
적용됐으며 stale-command 거절이 없었다. 내비게이터 높이를 82px 늘리고 재시작한
뒤에도 복원됐다. 실제 가운데 버튼을 누른 채 드래그하는 조작은 자동화 도구의
제약으로 미검증이다. 물리 펜 검증으로 대체해서 해석하지 않는다.

합성 구조와 최종 검증 상태는
[ADR-0046](decisions/ADR-0046-web-ui-over-native-canvas.md)을 따른다.
이 작업도 설치본 갱신, commit/push, 태그 생성 및 배포를 수행하지 않는다.
