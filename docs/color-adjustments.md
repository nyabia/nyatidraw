# 기본 그림 색 보정

W5의 최소 경로다. 메뉴의 **그림 색 보정**은 현재 래스터의 RGB를 보정한다.
색 선택기나 브러시 색 변경과 별개이며, 조정 레이어·마스크·필터 카탈로그는 포함하지 않는다.
선택이 있으면 선택한 픽셀만, 없으면 페이지 밖의 signed 타일까지 현재 레이어를 처리한다.
편집 잠금은 거부하며 투명도 잠금은 허용한다. 다른 레이어와 모든 픽셀의 alpha는 정확히 유지한다.
alpha 0의 숨은 RGB도 건드리지 않으며 빈 영역에 새 픽셀을 만들지 않는다.

## 값과 순서

모든 기본값은 0이며 기본값 미리보기·초기화·무변경 확정은 원본 바이트와 정확히 같다.
저장된 premultiplied linear RGBA8를 실수 정밀도의 straight sRGB로 바꾸어 다음을 적용한 뒤
기존 alpha로 다시 premultiply하고 linear RGBA8로 한 번 양자화한다.

1. 색상: -180~180도, HSV hue에 더하고 원을 따라 wrap한다.
2. 채도: -100~100%, HSV S에 `1 + 값/100`을 곱하고 0~1로 clamp한다.
   -100은 무채색이며 원래 무채색에 양의 값을 주어도 색을 만들지 않는다.
3. HSV 명도: -100~100%, HSV V에 같은 배율을 적용한다. HSL lightness가 아니다.
4. 대비: -100~100%, sRGB 각 채널에 `(채널 - 0.5) * (1 + 값/100) + 0.5`를 적용한다.
5. 밝기: -100~100%, 대비 결과에 `값/100`을 더한 뒤 0~1로 clamp한다.

## 미리보기와 저장

미리보기는 항상 대화상자를 열 때의 고정 원본·레이어·선택에서 다시 계산한다.
슬라이더를 반복 조절해도 이전 결과에 누적 적용하지 않는다. 미리보기는 문서 이력과 저장의
원본이 아니며, 확정 한 번에 변경이 있을 때만 Undo 한 단계가 생긴다. 취소·Escape·도구 전환과
창 닫기는 미리보기를 확정하지 않는다. 보정 중 다른 그림·레이어·선택 편집은 거부한다.
원본이나 선택이 바뀌었거나 실패한/오래된 미리보기 generation이면 확정을 거부한다.
Windows에서 보정 중 Save/Save As는 확정 또는 취소를 먼저 요청한다. 브라우저의 NTDR 저장과
이미 예약된 자동 복구는 미리보기 화면 대신 확정된 원본 snapshot을 읽는다.
숫자 입력을 마친 직후에는 입력값과 마지막으로 승인된 미리보기가 같아진 뒤 확정할 수 있다.

기존 sparse 타일만 순회하고 선택 밖은 보존한다. 선택과 변경 타일은 기존 편집 work/memory
상한을 적용하며 기존 preview와 새 candidate가 함께 살아 있는 메모리도 계산한다.
호스트가 표시할 수 없는 결과를 조용히 부분 표시하지 않고 미리보기 오류로 반환한다.

실제 UI 조작·물리 펜·기준 그림 W5 gate는 core 검사나 빌드로 대신하지 않는다.

## 로컬 검증 범위

후속 [워크플로우 연동 검증](measurements/workflow-integration.md)에서 웹 확정 후
내비게이터/레이어 썸네일의 캐시 갱신 누락을 수정하고 실제 UI로 재확인했다.
실제 웹 NTDR 다운로드→별도 브라우저 프로필에서 가져오기→PNG 바이트 일치도 확인했다.
아래 초기 검증의 브라우저 자동 복구 검사와는 별개다.

- CPU/core 검사는 중립값의 정확한 복원, alpha·선택 밖 픽셀 보존, 원본에서의 재계산,
  취소/무변경의 이력 불변 및 단일 확정을 다룬다.
- [Windows native 검증](measurements/color-correction-native.md)은 작성 스레드의 별도
  프로세스 재열기와 실제 ActiveCanvas/WGPU 경로를 구분한다. RTX 3080/Vulkan에서
  페이지 안팎의 미리보기·취소·확정·Undo/Redo와 scratch 저장/재열기를 통과했다.
- Playwright CLI로 격리된 Edge 프로필의 Dioxus 웹/Worker 디버그 빌드를 조작했다.
  숫자 입력과 밝기 미리보기, Escape 취소, 확정, 버튼과 Z/Shift+Z Undo/Redo를 확인했다.
  취소·Undo는 원본과, Redo는 확정본과 캔버스 픽셀이 정확히 같았다.
- 저장 완료 후 브라우저 프로세스를 종료하고 같은 시험 프로필로 다시 열었을 때에도
  확정한 그림 픽셀이 정확히 같았다. 이는 브라우저 작업 복구 검사이며 재시작 후
  Undo 이력 유지나 이번 기능의 웹 NTDR/native 상호운용 검사를 뜻하지 않는다.
- 캡처 비교는 1600×1000 viewport에서 동일한 캔버스의 RGBA 바이트로 수행했다.
  내용이 바뀌는 저장 알림이 있는 하단 48px만 비교에서 제외했다. 시험 획은 그 밖에 있다.
- 검사 중 발견한 대화상자 종료 후 BODY 포커스 문제를 수정했다. 이전 대상이 사라지면
  편집기 단축키 범위로 돌아가며 새 대화상자나 사용자가 옮긴 포커스는 빼앗지 않는다.

사용자 작품·설치본·실제 브라우저 프로필은 건드리지 않았다. 물리 펜, 데스크톱 창 표시,
iPad Safari, 고주사율 및 실제 일러스트 W5 작업은 미검증이다. 소스 업로드·배포는 하지 않았다.
