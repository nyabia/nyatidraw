# 드로잉 작업 동선 점검

이 문서는 공개 alpha.21 이후의 작업 동선 수정과 검증을 기록한다. 사용자가 후속 배포를
승인했으며, 릴리즈 담당자가 최종 검증과 공개 버전 확인 후 게시한다. 문서에 구현을
기록한 것만으로 배포·설치본 교체나 최종 검증이 완료됐다는 뜻은 아니다.
공용 `editor-ui`를 사용하며, Windows와 웹의 조작 계약을 맞춘다.

## 판단

기능의 유무보다 **편집 대상, 진행 중인 상태, 다음 조작, 그림으로 돌아오는 경로**가
일관되지 않은 것이 우선 문제다. Procreate와 Clip Studio의 공식 안내를 보면 선택·변형
중에는 그 상태의 조작을 노출하고, 브러시/레이어 설정은 대상과 역할을 구분한다.
경쟁 제품의 버튼 모양을 복사하는 것보다 이 흐름을 먼저 맞춘다.

[공식 자료 비교](research/drawing-ux-comparison.md)는 Procreate, CSP Simple, CSP Studio를
구분한다. 경쟁 제품 실기기 비교나 펜 감각 측정 결과는 아니다.

사용자가 정한 무채색 프레임, 도구/세부도구/속성/크기 빠른 선택의 분리,
G/B/E/F/C 단축키, 숫자 우측 정렬은 유지한다.

## 발견한 문제와 이번 수정

| 작업 | 기존 문제 | 로컬 수정 |
|---|---|---|
| 화면 이동 후 그리기 | 화면 이동에도 크기·불투명도·필압 속성이 나옴 | 화면 이동 전용 안내만 표시 |
| 레이어 선택 후 펜 복귀 | 읽기 전용 레이어 이름이 B/G 등의 키를 가로챔 | 이름을 편집할 때만 키를 가로채고, 일반 선택에서는 도구 단축키 허용 |
| 속성을 조절한 뒤 도구 전환 | 속성 패널 전체가 키를 가로챔. 추가 옵션·체크박스에서 복귀가 끊김 | 실제 숫자 입력만 보호. 숫자의 Ctrl+A는 그림 전체 선택을 실행하지 않음 |
| 선택 후 채색 | 펜으로 바꾸면 선택 관련 조작이 속성에서 사라짐 | 선택이 유지되는 동안 캔버스 위 별도 행에 상태·변형·복사·해제 표시. 그림 위를 덮지 않음 |
| 선택 추가/빼기 | 현재 조합을 드롭다운을 열어 찾아야 함 | 새 선택/추가/빼기를 눌러 선택하는 세 버튼으로 표시 |
| 전체 레이어 크기·회전 수정 | 엔진은 전체 그림 변형을 지원하지만 UI는 선택을 강제 | 잠금·마스크·재생 등의 제한을 지키면서 선택 없이 전체 레이어 변형 시작 |
| 변형 수치 조정 | 입력한 수치를 버리고 이전 미리보기를 도구 전환으로 확정할 수 있음 | blur/Enter로 미리보기. 정확한 값이 확인되기 전 적용·자동 확정 도구 전환 차단. 오류 시 입력 보존 |
| 변형 종료 | Enter 안내가 숫자 입력칸 안에서만 실제로 작동 | 캔버스/편집기 초점에서도 검증된 미리보기의 Enter 확정. 명시적 적용/취소 버튼 유지 |
| 비동기 미리보기 실패 | 큐 접수 후 거절되면 재시도가 계속 막힐 수 있음 | 최신 거절 이벤트와 프로젝트 교체를 관찰해 대기 해제. 수치는 보존 |
| 마스크를 다듬다가 같은 레이어 클릭 | 이름을 누르면 이미지 대상으로 바뀜 | 같은 활성 레이어의 이름/정보 클릭은 마스크 대상을 유지. 이미지 썸네일은 명시적 이미지 선택 |
| 마스크 대상에서 그림 이동 | 지원하지 않는 가운데 정렬이 활성으로 보임 | 이미지 대상으로 돌아가는 버튼을 표시하고 잘못된 대상의 정렬을 비활성화 |
| 레이어 정렬 | 작은 삭제 버튼이 이동 핸들 바로 위에 붙음 | 행별 삭제 제거, 하단의 선택 대상 삭제로 모음. 이동 핸들은 행 높이를 사용 |
| 마스크 메뉴 | 대상 레이어를 눈으로 구별하기 어렵고 삭제가 다른 명령과 붙음 | 실제 대상 이름·편집 상태 표시. 마스크 제거는 취소가 기본인 별도 확인 단계 |
| 애니메이션에서 그리기로 복귀 | 타임라인을 숨겨도 재생이 남아 편집 불가 상태가 숨겨짐 | 상단 토글과 패널 닫기 모두 정지 성공을 확인한 뒤 닫음. 실패하면 패널·오류 유지 |
| 캔버스 크기 변경 | 명령 큐 접수만으로 창을 닫고 성공처럼 보임 | 실제 캔버스 결과 확인 후 배경 설정 적용·닫기. 거절/실패 시 초안과 오류 유지 |
| 좁은 상단 툴바 | 라벨이 숨겨지면 캔버스는 빈 버튼, 취소는 Esc만 남음 | 각각 독립 아이콘과 접근성 이름 제공. 저장·도구 선택 상태도 명시 |
| 선택 명령 실패 | 내부 오류 상태가 화면에 표시되지 않음 | 해당 조작 영역에 오류 표시 |
| 레이어 옵션 찾기 | 작은 행 아이콘의 의미와 적용 대상을 알기 어려움 | 대상 이름과 편집 상태를 표시하는 공용 레이어 옵션 메뉴. 오른쪽 클릭·옵션 버튼·Shift+F10으로 접근하고 삭제는 별도 확인 |
| 아이콘·작은 조절기 이해 | 브라우저 기본 도움말에 의존하며 키보드 초점에서는 찾기 어려움 | 공용 hover/focus 도움말. 기존 명령 설명과 접근성 이름을 사용하고, 조작 중·터치 접근에서는 팝업을 강제로 띄우지 않음 |
| 웹에서 연속해서 그리기 | 자동 복구 저장의 대기·진행·완료가 매획 긴 알림으로 바뀜 | 자동 복구 상태를 작은 점/체크로 분리. 반복 live 알림은 제거하고 오류 경고·명시적 다운로드 확인은 유지 |
| Windows에서 그림 이동 | 드래그 중 실제 그림의 이동 결과를 확인하기 어려움 | 원본에서 계산한 일시적 그림 미리보기. 확정 전 결과가 작품 히스토리에 섞이지 않도록 분리 |

선택 해제와 변형 취소는 다르다. 변형 후 유지된 선택을 해제하는 것은 별도 조작이며,
선택도 히스토리 대상이므로 그 뒤의 Undo는 선택 해제부터 되돌릴 수 있다.
이번 수정에서 히스토리 계약을 바꾸지 않는다.

## 다음 배치 제안 — 아직 구현하지 않은 것

### 1. 태블릿에서 그림 공간부터 확보

1194×834에서 좌측 도구/속성 및 우측 팔레트가 많은 폭을 차지한다. 1024×768에서는
실제 측정한 앱 셸 폭이 1100px여서 오른쪽이 잘린다. 이는 아이콘 크기만 줄여서는 해결되지 않는다.

제안은 별도 편집기를 만드는 것이 아니라 **같은 도킹 모델의 태블릿 작업공간**이다.

- 도구·크기·불투명도는 바로 접근 가능하게 유지한다.
- 세부도구 목록은 선택된 도구를 다시 눌러 펼치고, 기존 독립 패널로 고정할 수도 있게 한다.
- 우측에는 레이어를 우선 노출하고 색상환/내비게이터를 접거나 탭으로 교대한다.
- 색상환을 여는 동안 최근 색상은 계속 접근 가능하게 한다.
- 사용자 저장 레이아웃을 강제로 초기화하지 않는다. 좌우 손잡이 배치도 이 작업공간에서 결정한다.

목표는 일반 가로 화면에서 캔버스 영역이 대략 4:3~16:9에 가까워지는 것이다.
모든 화면 비율에 강제하지 않으며, 펜으로 필요한 버튼을 쉽게 누를 수 있는지도 함께 확인해야 한다.

### 2. 메뉴를 명령의 긴 목록에서 작업별 진입점으로

현재 메뉴에는 새 그림·가져오기·작업 저장·PNG·스프라이트 시트·클립보드·애니메이션·보정·설정이
가로로 이어진다. 메뉴를 열었는데 다음 조작을 찾기 위해 가로 스크롤해야 한다.

기존 툴바를 덮는 동작은 유지하면서 **파일 / 편집 / 캔버스 / 애니메이션 / 설정**으로
묶는 안을 제안한다. 파일 안에서는 계속 편집할 NTDR 저장과 결과물 PNG 내보내기를 구분한다.
잘라내기·복사·붙여넣기는 편집으로, 출력 크기는 내보내기로 둔다. 단축키는 각 명령 옆에 유지한다.

### 3. 레이어 옵션 메뉴 이후의 기본 행 정리

Solo/참조/클리핑/잠금/마스크 등의 공용 옵션 메뉴는 이번 후속 수정에 구현했다.
기본 행을 표시·썸네일·이름·편집 대상·순서 이동 중심으로 더 단순하게 할지는 별도 제안으로
남긴다. 빠른 접근을 위해 남길 아이콘은 실제 작업을 확인해 결정하며, 메뉴 추가를 근거로
기존의 빠른 조작을 모두 없애지 않는다. 마스크가 있으면 이미지/마스크 썸네일 둘은 유지한다.

칠하기 경로는 `선화 참조 지정 → 밑색 레이어 선택 → 채우기 → 펜 복귀`로 점검한다.
‘자료 이미지 참조’와 ‘채우기의 경계 참조’를 같은 모호한 이름으로 표시하지 않는다.
행별 삭제는 안전하게 분리했고, 옵션 메뉴의 삭제 역시 취소 가능한 확인 단계로 제공한다.
태블릿 작업공간 전체 재배치는 이번 범위에 포함하지 않았다.

## 이전 로컬 UX 묶음의 검증

환경은 Windows의 Edge Chromium, 로컬 release WebAssembly 빌드이다.
1194×834(iPad 크기·터치 에뮬레이션), 1920×1080, 잔여 문제 확인용 1024×768로 검사했다.
키보드/포인터 조작은 브라우저 자동화이며 실제 iPad Safari·Apple Pencil·Windows 펜 검증이 아니다.

- `cargo clippy -p nyatidraw-editor-ui -- -D warnings` 통과.
- `cargo check -p nyatidraw-desktop` 통과.
- `tools/build-web.ps1 -BasePath '/'` release UI/worker 빌드 통과. 배포하지 않음.
- 레이어 이름 클릭 후 B, 추가 옵션에서 E, 숫자 Ctrl+A/Enter, 도구 전환 후 선택 유지·해제 통과.
- 전체 레이어 변형 시작, 잘못된 배율 초안 보존·적용 차단, 취소, 수치 미리보기, 캔버스 초점 Enter 확정 통과.
- 시험 PNG의 16px 수평 이동에서 모양/색 보존. 변형 직후 한 번 Undo와 취소 결과는 기준 RGBA와 정확히 일치.
- NTDR 저장 → 브라우저 프로세스 종료 → 재시작 → 파일 열기 → PNG 출력의 RGBA 일치.
- 캔버스 256×128 변경 후 동일한 종료/재열기 절차에서 크기 및 RGBA 일치.
- 같은 레이어 클릭의 마스크 대상 유지, 이미지 이동 제한 및 명시적 이미지 복귀 통과.
- 상단/패널 두 타임라인 닫기 경로 모두 재생 정지 후 닫힘. 다시 열면 프레임을 유지하고 정지 상태.
- 실제 네이티브 창의 비동기 export 거절 경쟁 조건, 장시간 드로잉, 실기기 터치 오탭률은 미검증.

추가 UI 단위 테스트는 만들지 않았다. 기존 코어/저장 포맷은 변경하지 않았으며,
브라우저 검증 스크립트·시험 파일·화면 캡처는 Git 제외 경로 `output/playwright/ux-workflow/`에 둔다.

주요 로컬 자료:

- `before-ipad-ready.png`: 변경 전 실제 UI.
- `after-ipad-final.png`, `after-desktop-final.png`: 변경 후 선택 문맥과 공용 UI.
- `narrow-layout-remaining.png`, `narrow-results.txt`: 미해결 1100px 최소 폭.
- `context-results.txt`, `mask-results.txt`, `artwork-results.txt`, `lifecycle-results.txt`, `pixel-results.txt`: 실행 증거.
- `transformed.ntdr`, `resized.ntdr` 및 대응 PNG: 재열기/픽셀 비교 시험 자료.

다음 단계의 합격 조건은 버튼 수가 아니라 **러프 → 선화 → 밑색 → 수정 → 저장/출력**을
진행하면서 숨겨진 선택, 잘못된 대상, 종료 방법이 없는 모드 때문에 멈추지 않는 것이다.

## 후속 묶음의 검증 상태

릴리즈 담당자가 Windows Edge의 1440×1000 브라우저에서 후속 동작을 확인했다.
공개 main과 최신 alpha.21을 확인했으며 다음 릴리즈 번호는 alpha.22로 확정했다.
아래는 그 실행 결과이며, 웹에서 확인한 결과를 네이티브 창이나 물리 펜으로 확대하지 않는다.

| 확인 항목 | 확인한 동작과 경계 | 상태 |
|---|---|---|
| 레이어 메뉴 | 옵션 버튼/Shift+F10 열기, 삭제 확인에서 Esc 두 번으로 닫기와 초점 복귀, 마스크 추가·제거 확인 취소. 상시 마스크 추가 버튼은 없음 | 통과 |
| 도움말 | 화면 안 배치와 기존 접근성 이름 유지. 물리 터치·펜에서의 방해 여부는 별도 | 브라우저 통과 |
| 자동 복구 | 완료 표시 `자동 복구 ✓`, `aria-live="off"`, 성공 시 alert 0개. 실패 유지 경로는 소스 확인이며 실패 주입 실행은 미검증 | 성공 경로 통과 |
| 파일 작업 | 새 브라우저 프로세스의 자동 복구 및 명시적으로 저장한 NTDR 재열기에서 종료 전 PNG와 정확히 같은 RGBA | 통과 |
| 웹 그림 이동 | 마우스 버튼을 누른 채 실제 그림 이동, 놓은 직후 동일한 표시, Undo·취소에서 원래 위치 복원 | 통과 |
| 임베드 | 공개 iframe 데모에서 64×64 새 그림으로 교체, 자동 복구 표시/실패 alert 0개, 완료 시 호스트 PNG 수신 | 통과 |
| Windows 그림 이동 | 드래그 중 실제 그림, 취소 시 원본 복원, 확정·Undo, NTDR 저장→종료→재열기 보존 | 대기 |
| 내비게이터 넘침 수정 | 1194×834에서 정사각형·세로 그림의 비율 유지, 하단 1:1 버튼 실제 클릭, 썸네일 중심 클릭·드래그 | 통과 |

웹 이동 시험에서 화면의 그림 경계는 `(371, 432, 395, 456)`에서
`(387, 440, 411, 464)`로 변했고, 버튼을 놓은 뒤에도 일치했다. Undo·취소 뒤에는
원래 경계로 돌아왔다. 문서 픽셀의 `(+16, +8)` 이동 후 출력 PNG의 빨간 영역 경계는
`(36, 48, 60, 72)`였다.

재시작/재열기 픽셀 비교 기준은 **종료 직전에 앱이 출력한 PNG**다. 최초 가져오기 원본
PNG와는 기존 색 변환에서 채널 값 최대 2 차이가 있었으므로, 원본 PNG와 정확히
일치한다고 주장하지 않는다. 자동 복구와 명시적 NTDR 재열기는 각각 종료 전 출력과
RGBA가 정확히 일치했다.

최종 전체 workspace Clippy, WebAssembly Clippy, 포맷 검사, 핵심 테스트 280개 및
Windows/웹 release 빌드가 통과했다. 1194×834 터치 에뮬레이션에서 비선택 레이어의
옵션을 열어 잠금을 바꾸어도 현재 그림 레이어 선택이 유지됨을 확인했다.
같은 환경의 DPR 2에서 CSS 좌표 (+16,+8)는 문서 (+32,+16)로 이동하며,
가져오기 직후 앱 출력 PNG에 이 이동을 적용한 예상 RGBA와 실제 결과가 일치했다.
한 번의 Undo도 같은 기준 PNG와 정확히 일치했다.

Windows release 시험 창을 실행했으나 수동 창 제어가 중단되어 네이티브 이동의
최종 표시 검사는 완료하지 않았다. CI 및 공개 자산 결과는 [배포 기록](releasing.md)에
이어 기록한다. 실행·합성 입력·코어 검사만으로 물리 펜 사용감을 증명하지 않는다.

자동 복구 표시는 캔버스 모서리에 고정하며 레이아웃 여백이나 입력 영역을 차지하지 않는다.
반복 상태는 `aria-live="off"`이고, reduced-motion 설정에서는 점이 정적으로 표시된다.
명시적 파일 작업의 일반 확인은 잠시 표시하고, 저장 실패 경고는 자동으로 숨기지 않는다.
브라우저가 다운로드 요청을 받은 것과 사용자가 파일 보관을 확인한 것은 구분한다.

Windows의 기존 [마스크 최종 표시 문제](research/native-mask-presentation.md)는 이 UX 수정으로
해결됐다고 간주하지 않는다. 실제 iPad Safari·Apple Pencil, 물리 Windows 펜, 고주사율
표시 지연과 설치 업데이트는 별도 증거가 없는 한 미검증이다.
