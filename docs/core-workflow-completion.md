# 기본 드로잉 작업의 남은 연결

기준은 [일러스트 워크플로우 W0–W5](illustration-workflow.md)다. 기존 구현을 지우거나
새 UI를 따로 만들지 않고, 현재 작업 트리에서 실제로 빠진 기본 조작을 연결한다.
공개판·설치판의 기능 목록이나 모든 실사용 gate의 합격 선언이 아니다.

## 이번 로컬 구현 범위

| 작업 | 의미와 보존 조건 | 검증 상태 |
|---|---|---|
| 이미지를 레이어로 가져오기 | PNG를 현재 그림에 추가하고 배치·변형 후 확정 또는 취소. 기존 그림과 출력 크기를 교체하지 않음 | 핵심·웹 조작·Undo·별도 프로세스 재열기 통과 |
| 그룹 복제 | 하위 그룹·래스터·순서·클리핑·표시 속성을 보존하며 독립 ID로 복제. 이후 수정은 원본에 영향 없음 | 핵심·웹 그룹 구성/복제·별도 프로세스 재열기 통과 |
| 두 색 그라데이션 | 전경→투명 및 전경→배경. 획 시작 시 색과 모드를 고정. 선택이 없으면 출력 페이지, 선택이 있으면 signed 선택 범위 | 핵심·웹 조작·Undo/Redo·설정과 그림 재열기 통과 |
| 마법봉 선택 조합 | 새 선택·추가·빼기. 페이지 밖 seed와 관련 source 타일도 유한 작업 범위에 포함 | signed 범위 핵심 검사·웹 선택 조합/삭제/Undo 통과 |
| 자유 각도 화면 회전 | 숫자 각도 및 Shift+Space+좌우 드래그. 화면 중심의 문서 좌표 유지. 그림·Undo·PNG는 바꾸지 않음 | 입력 좌표 검사·웹 숫자/드래그 회전·PNG 불변 확인 |
| 참조 이미지 보조창 | 내비게이터의 참조 탭에서 PNG 한 장을 맞춤·확대/축소·이동·비우기. 세션 전용이며 문서와 분리 | 웹 PNG 로딩·확대·이동·탭 복원·PNG 불변·재시작 비저장 확인 |
| Windows 비트맵 붙여넣기 | private exact/PNG 우선, DIBV5/DIB 읽기 추가. 기존 임시 붙여넣기·확정·취소 사용 | DIB 포맷/경계 검사·임시 붙여넣기 확정/취소/재열기 통과. 실제 OS 클립보드 미검증 |

그라데이션과 마법봉은 양쪽 앱이 같은 editor/paint CPU 코어를 사용한다. 레이어 가져오기와
복제도 임시 변형·구조 이력을 재사용하며 별도 웹 전용 그림 포맷을 만들지 않는다.
도구 설정 레코드는 새 그라데이션 모드를 보존하도록 버전이 올라가며, 이전 레코드에는
전경→투명 기본값을 적용한다. 이는 작품 타일 스키마 변경과 별개다.

## 그라데이션·마법봉 사용

- 그라데이션 도구(F)의 **색 연결**에서 전경→투명 또는 전경→배경을 고르고 시작점에서
  끝점까지 끈다. 배경색을 바꾸려면 X로 두 색을 교환하고 색 패널에서 색을 고른 뒤 X로
  되돌린다. 선택이 없으면 페이지 안에만 칠하고, 선택이 있으면 페이지 밖 선택도 포함한다.
  투명도 잠금은 기존 알파를 보존한다. 적용된 그림은 Undo로 되돌린다.
- 마법봉의 **선택 조합**에서 새 선택·추가·빼기를 고른 다음 원하는 연결 영역을 누른다.
  참조 범위와 허용 오차는 마법봉 설정이며 채우기 설정과 독립적이다. 선택 조합 자체는
  그림을 바꾸거나 Undo 이력을 소비하지 않는다. 너무 넓은 범위는 기존 선택을 유지하며 거절한다.

## 안전한 유한 범위

- 무한 작업 공간이 무한 크기 dense 선택 마스크를 뜻하지 않는다. 마법봉은 출력 페이지,
  실제 참조 타일 범위와 seed를 포함하는 유한 범위를 쓰고, 자원 한도 초과 시 기존 선택을
  유지하며 거절한다. 멀리 떨어진 그림이 매우 넓은 경계를 만들 수 있다.
- 선택 없는 그라데이션은 출력 페이지까지만 적용한다. 페이지 밖에 칠하려면 명시적인
  사각/올가미/마법봉 선택을 만든다. 내부 임시 페이지 마스크를 UI 선택으로 남기지 않는다.
- PNG 가져오기 도중 다른 프로젝트로 바뀌면 늦게 도착한 파일을 새 프로젝트에 삽입하지 않는다.
  파일 선택 취소나 디코딩 실패는 기존 그림·클립보드를 바꾸지 않는다.
- DIB는 24/32비트 BI_RGB 및 32비트 BI_BITFIELDS만 읽는다. 행 정렬·상하 방향·명시 알파를
  해석하며, BI_RGB의 예약 바이트를 투명도로 오해하지 않는다. 알 수 없는 압축/프로파일은
  추정해서 색을 바꾸지 않고 PNG 가져오기를 안내한다. 사용자 클립보드에 시험 데이터를 쓰지 않는다.

## 참조 이미지·보기 회전

- 내비게이터 패널의 **참조** 탭에서 PNG 한 장을 연다. 맞춤, 확대/축소, 이미지 드래그,
  비우기를 제공한다. 탭·도킹 전환에는 남지만 앱 종료 후에는 남지 않는다. 이미지나 파일 경로를
  프로젝트에 넣지 않으며 레이어·Undo·PNG 출력도 바꾸지 않는다.
- PNG는 72 MiB 이하, 가로·세로 각각 4096 px 이하로 제한한다. 기존 PNG 디코더로 색과
  크기를 검사하고 표시용 PNG로 다시 인코딩한다. 한 번에 하나만 읽으며 취소·실패는 기존
  참조를 유지한다. 읽는 도중 비우기는 늦은 결과를 무효화한다. Windows 파일 읽기·디코딩은
  별도 스레드에서 수행하며, 브라우저는 비동기 파일 읽기 후 WASM PNG 디코더를 사용한다.
- 보기 회전 숫자는 도 단위로 입력한다. **Shift+Space+좌우 드래그**는 논리 픽셀당 0.5도씩
  회전한다. 0° 버튼은 확대 배율·좌우 반전·화면 중심 문서 좌표를 유지하며 각도만 초기화한다.
  가운데 마우스 버튼과 펜의 화면 이동 버튼은 기존 이동 동작을 유지한다.
- `cargo test -p nyatidraw-input` 10개와 해당 패키지 all-targets Clippy `-D warnings` 통과.
  임의 각도·반전·페이지 밖 좌표·여러 바퀴 회전의 중심 및 표시/입력 좌표 왕복을 검사했다.
  이 결과는 실제 UI 조작·물리 펜·고주사율 디스플레이 검증을 대신하지 않는다.

DIB 경계 근거: [Windows 표준 클립보드 형식][D1], [BITMAPV5HEADER][D2],
[비트맵 행 정렬][D3]. 그라데이션의 선택 유무에 따른 범위는
[Krita 그라데이션 도구][K1]의 기본 조작과 같은 방향이며 고급 종류를 모두 복제하지 않는다.

## 통합 검증 결과

최종 작업 트리에서 아래 명령이 통과했다. 기존 vendored Wry/Dioxus 경고는 앱 자체의
엄격한 Clippy 검사와 별개로 남아 있다. 새 의존성은 추가하지 않았다.

- `cargo test --workspace --all-features --locked --quiet`: 전체 통과. 데스크톱 59개 통과,
  기존 5개 ignored 유지. editor 그라데이션/마법봉 3개, project-web 13개,
  web-core 12개를 포함한다. 별도 자식 프로세스 저장/재열기도 통과했다.
- `cargo clippy --workspace --all-targets --all-features --locked -- -D warnings`
- `cargo clippy -p nyatidraw-web -p nyatidraw-web-worker --target wasm32-unknown-unknown --locked -- -D warnings`
- `cargo fmt --all -- --check`, CRLF-aware `git diff --check`, `node --check apps/web/src/browser.js`
- `tools/build-dev.ps1` Windows release 및 `tools/build-web.ps1 -BasePath /` 웹 UI/Worker release.
  사용한 Rust는 저장소 설정의 1.96.0, Dioxus CLI는 0.7.9다.

### 실제 웹 릴리즈 조작

격리된 Edge 프로필에서 기존 합성 그림 `workflow-final.ntdr`를 열었다. 사용자 원본은
사용하지 않았다. Playwright 마우스/키보드 입력이며 물리 펜 입력을 흉내 낸 증거가 아니다.

1. PNG 레이어 가져오기 → 취소: 출력 크기 1280×720와 모든 RGBA 픽셀 보존.
2. 참조창 PNG 열기 → 125% 확대 → (25,12) 이동 → 내비게이터/참조 탭 왕복:
   참조 변환 유지. 보기 회전 숫자 37.5°와 Shift+Space 80 px 드래그의 40°를 확인했다.
   원본 PNG 출력은 모든 픽셀이 같았다.
3. PNG 재가져오기 → (240,60) 이동 미리보기 → 확정: 그림 변화, 페이지 크기 유지.
   한 번의 Undo로 가져오기 전 모든 픽셀 복원. Redo 후 PNG와 NTDR 저장.
4. 레이어 썸네일 드래그로 새 그룹에 가져온 그림 배치 → 그룹 선택 → 전체 복제.
   원본/복사 그룹과 자식 레이어가 UI에 표시됐다. 중첩 metadata·원본 독립 편집은
   별도의 핵심/새 프로세스 검사로 확인했다.
5. 복제 그룹에 새 레이어 → 전경/배경 그라데이션 → Undo/Redo: 페이지 내부 칠과
   단일 Undo의 정확한 원상복원 확인. 마법봉 새 선택 → 추가 → 빼기 후 선택 픽셀 삭제,
   Undo로 그라데이션 PNG를 정확히 복원했다.
6. 최초 브라우저 프로세스 종료 → 별도 새 프로필에서 가져오기 결과와 최종 NTDR를 각각
   열고 출력: 각 저장 PNG의 모든 RGBA 픽셀과 일치. 그룹·자식·그라데이션 모드도 복원됐다.
   참조 이미지는 프로젝트에 저장되지 않았다.
7. 두 번째 브라우저 종료 → 같은 프로필 재시작: Worker/IndexedDB 자동 복구의 그림과
   그라데이션 설정 복원. 출력은 최종 PNG와 모든 픽셀이 일치했다.
8. 네이티브 CLI `validate`로 웹 저장 파일 두 개를 읽어 각각 유효한 nonempty root 확인.

검증용 파일·캡처·테스트 로그는 ignored `output/playwright/core-*`에 남겼다.
검증 브라우저와 루프백 서버는 종료했다. 콘솔에는 로컬 favicon 404, Chromium의
WebGPU power-preference 경고, 비차단 autofocus 안내만 있었다.

디코딩한 PNG RGBA SHA-256:

- 원본/가져오기 취소/참조·회전 후: `3c662619bbfbd1240cccd445cf1e1da5b2df3327167db985c2033672bc7e8c75`
- 가져오기 확정/별도 프로세스 재열기: `6c60df1665d847491238254ffa2edad94b909dda8759e78c9d59de6059cf0a81`
- 최종/선택 삭제 Undo/별도 프로필 재열기/자동 복구: `af0459c500d48c32e2007e012e1176ed3174da930435f8c66c4c441c27abd3a3`

Windows release 실행 파일 SHA-256:
`f0e5e920ba0f275adf35527ca8bf00bd10b37d737e8af244766f8adb82e8f192`.
설치본 교체나 배포를 뜻하지 않는다. 네이티브 창의 파일 대화상자·클립보드 실사용,
실제 펜·고주사율·W0 기준 그림 완성은 이번 결과로 검증하지 않았다.

## 아직 없는 기능과 별도 gate

- 여러 레이어/그룹 동시 변형: 현재 변형은 래스터 하나가 대상이다. 선화·밑색·그림자를
  함께 회전/확대하는 형태 수정은 아직 막힌다. 단일 레이어 이동과 구별한다.
- 부드러운 선택 경계/feather: 선택 coverage는 이진 값이다. alpha에서 선택을 만들거나
  부분 색 보정을 해도 원래 fractional alpha를 선택 강도로 보존하지 않는다.
- 전체 그림 리샘플링/축소 출력: 캔버스 크기는 출력 범위를 바꾸는 기능이며 그림 전체를
  리샘플링하지 않는다. PNG를 절반 크기로 내보내는 별도 경로도 아직 없다.
- 참조창의 색 채취: 이번 참조창은 표시·이동 전용이다. 캔버스 스포이트와 같은
  자료색 채취 기능은 없으며, 작품 레이어로 가져온 이미지는 기존 스포이트로 읽을 수 있다.
- 레이어 마스크: 비파괴로 숨기고 다시 드러내는 작업은 아직 없다. 선택 마스크·alpha lock·
  clipping을 레이어 마스크라고 부르지 않는다. 지속 형식, 마스크 그리기, 합성·picker·export·
  Undo를 함께 설계해야 한다.
- 레이어 병합: clipping stack과 아래 합성 배경에 의존하는 모드의 외형 보존 규칙을 먼저 정해야 한다.
  그룹 복제가 병합을 대신 구현한 것은 아니다.
- Screen/Add 등 추가 합성 모드, 혼색·수채·고급 질감 브러시, 벡터·애니메이션,
  macOS/Linux 구현은 기존 보류를 유지한다.
- 특허 검토가 필요한 둘러싸서 채우기·선 넘침 방지 등의 기존 계획 보류도 유지한다.
- 실제 펜 감각·고주사율·설치본 창 조작·기준 일러스트 완성은 합성 입력이나 핵심 검사만으로 합격하지 않는다.

이 목록의 미구현 항목을 숨긴 채 '일반 드로잉 앱 완성'이라고 선언하지 않는다.
위 검증 당시에는 소스 업로드·태그·배포·설치본 교체를 수행하지 않았다.
이후 사용자가 무파일 낙서 흐름의 보완과 배포를 승인했다. 게시 결과는
[릴리즈 기록](releasing.md)으로 구분하며 설치본과 사용자 작품은 자동 교체하지 않는다.
