# 현재 우선순위와 다음 작업

## 이번 묶음: 웹 편집 연결과 그림 이어하기

범위는 기존 기능의 호스트 연결 및 다시 열기 UX다. W5·고급 브러시·반복을 함께
착수하지 않는다. 구현과 배포 확인은 별도로 기록한다.

1. **양쪽 편집 동작 일치** — 공용 선택·픽셀·레이어·변형 실행을 사용한다.
   변형 중 도구를 바꾸면 유효한 변경/붙여넣기를 확정하고, 변경 없는 변형만 취소한다.
   확정 실패 시 도구를 바꾸거나 초안을 버리지 않는다. 명시적 취소/Esc는 기존 의미를 유지한다.
2. **저장 위치 없는 새 그림** — 투명 래스터 한 장을 즉시 시작한다.
   Sketchbook에 이름 충돌 없는 `.ntdr`을 보관하고, 필요하면 다른 이름으로 저장한다.
3. **다음 실행에서 찾기** — 인자 없이 시작하면 최근에 정상적으로 연 그림 중
   존재하는 파일을 이어 연다. 버거메뉴에서 최근 그림 최대 20개를 선택한다.
   CLI 파일·명시적 프로젝트 환경변수는 이 기본값보다 우선한다.
4. **검증 후 출하** — 핵심 편집·저장/별도 프로세스 재열기, 격리 브라우저 조작,
   desktop/web 빌드와 Clippy를 확인한다. 실제 펜·설치 업데이트는 별도 증거다.

### 로컬 검증 상태 (공개 전)

- 전체 workspace 테스트/Clippy, WASM 웹 Clippy와 DX Windows·웹·Worker release 빌드 통과.
- 웹 변형 후 도구 전환, NTDR 다운로드, 별도 브라우저 프로세스의 자동 복구를 확인했다.
- 격리된 Windows debug/release 앱의 실제 메뉴에서 새 그림 생성과 최근 파일 전환을
  확인했다. release에서 새 항목은 메뉴를 다시 열지 않아도 목록에 나타난다.
- 새 그림의 흰 래스터 추가→Save→PNG export 완료를 확인했다. Scratch 프로젝트만
  사용했으며, 이동한 최근 파일은 알림과 함께 거절하고 현재 그림을 유지했다.
- 인자 없는 별도 release 프로세스가 최근에 연 기존 그림을 같은 content root로
  재개했다. 이번 새 그림 자체의 마지막 재실행은 실행 정책 차단으로 확인하지 못했다.
- Windows 캡처/커서 접근 실패로 제목 표시줄 정상 종료와 네이티브 캔버스 육안 검증은
  남는다. 검증 프로세스만 종료했으며 사용자 작품·설치 앱은 교체하지 않았다.
- 사용자가 배포를 승인했다. `v0.1.0-alpha.14`의 공개 결과는 [배포 기록](../releasing.md)에
  별도로 확인하며, 로컬 설치본은 교체하지 않는다.

## 최근 그림과 보관의 의미

- 최근 목록은 로컬 설정에 **경로만** 기록한다. 프로젝트 데이터·Undo에는 넣지 않는다.
- 파일을 정상적으로 연 뒤 writer에서 목록을 갱신한다. 실패한 열기로 마지막 그림을
  교체하지 않으며, 파일 저장 실패와 목록 저장 실패를 혼동하지 않는다.
- 기존 목록이 손상됐으면 덮어쓰지 않는다. 새 설정 파일은 임시 파일 후 교체한다.
- 삭제·이동된 최근 항목을 선택하면 다시 위치를 고르도록 알린다. 원본/PNG를 삭제하거나
  Sketchbook을 자동 청소하지 않는다. 최근 목록 20개 제한은 작품 보관 개수 제한이 아니다.
- 이전 버전의 `Sketchbook/작업 중.ntdr`은 최근 파일이 없을 때의 시작 위치로 유지한다.
- 테스트용 `NAYATI_LAYOUT_PATH`를 주면 Sketchbook·최근 목록도 그 설정 폴더에 격리한다.
- 웹은 현재 작업 한 개의 브라우저 복구를 유지한다. 데스크톱처럼 모든 임의 경로를
  재개하는 기능은 제공하지 않는다. 중요한 그림은 `.ntdr`로 내려받는다.

## 그다음 기획상 빈칸

| 우선순위 | 사용자가 얻을 결과 | 결정해야 할 경계 |
|---|---|---|
| W5 마무리 | 선화 색 바꾸기, 부분 명도/색 수정, 지우지 않고 가리기 | 레이어 색상화·기본 HSV·래스터 마스크를 작은 묶음으로 나누고 저장/재열기까지 검증 |
| 게임용 반복 | 가로/세로 반복 경계를 보며 타일 그림 제작 | X/Y 독립, 표시 복사본 읽기 전용, 페이지 밖 원본 보존. [기존 설계](../research/repeat-implementation.md) |
| 일상 보관 UX | 여러 연습 그림을 찾고 필요 없는 복구본을 정리 | 이번 최근 목록 이후의 갤러리·미리보기·명시적 삭제 정책. 자동 삭제는 하지 않음 |
| 웹 호스트 차이 | OS 클립보드·오래된 이력·로컬 파일 활용 | 공용 편집 코드를 복제하지 않고 브라우저 권한과 저장 한도를 먼저 결정 |

자료 이미지 패널, 고급 채색 보조, 메시 변형, 질감/습식 브러시, 타임랩스·애니메이션은
후속이다. 요청 기록과 특허 검토가 남은 기능은 구현 완료로 표시하지 않는다.
