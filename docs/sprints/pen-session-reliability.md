# 펜 작업 중단과 설정 복원 보수

목적: 실제 낙서를 계속할 수 있게 입력·저장 안정성을 먼저 보수한다.
사용 중인 설치본과 사용자 작품은 건드리지 않는다. 실행 테스트 전에 알리고,
물리 펜 검증과 창 없는 핵심 로직 검증을 구분한다. 사용자의 후속 승인에 따라
남은 보수와 저장 용량 개선을 합쳐 alpha.12로 배포한다.

## 수정 범위

| 문제 | 수정 방향 | 확인해야 할 것 |
|---|---|---|
| `Seal(NoAffectedTiles)` 이후 전체 편집 정지 | 정상 검증을 통과했지만 칠할 타일이 없는 획은 완료만 전달한다. 저장·히스토리·ID를 진행시키지 않는다. 다른 획 검증 실패는 무시하지 않는다. | 필압 0/불투명도 0 접촉 사이의 정상 획 저장, 새 프로세스 재열기 |
| 오류 안내가 모든 패널에 반복되고 종료창도 클릭 불가 | 캔버스 입력 호스트를 오류 화면에서도 유지한다. 입력 라우터 해제 시 WebView의 입력 영역을 반드시 복원한다. 오류 안내는 캔버스에 한 번만 표시한다. | 정상→오류→종료 경고→종료/재열기, 마우스와 펜 각각 |
| 축소할 때 GPU 타일 한도 초과 | 화면 전체 타일을 한 번에 고정하지 않고, GPU 저장 공간 범위 안에서 나눠 합성한다. 타일을 생략하거나 한도 숫자만 늘리지 않는다. | 실제 한도보다 많은 바깥 그림, 저배율·회전·다중 레이어·진행 중 획 |
| 펜으로 색상환 조작 실패 | WebView에서 시작한 펜 입력 소유권 유지, 캡처 종료 처리, 색상 선택 중 무관한 히스토리 revision 변경에 대한 방어 수정 | 색상환·SV·명도, 경계 밖 드래그, 저장 완료와 겹치는 선택 |
| 그림을 그려도 입력란 포커스 유지 | 캔버스 입력 경로에서 DOM 입력란을 blur하고 앱 셸에 포커스를 준다. WebView의 키보드 입력은 유지하며 패널 위 펜 조작은 그대로 둔다. | 수치 입력→펜 드로잉→단축키, 수치 입력 완료 여부 |
| 펜 사이드 버튼 | 한 버튼은 누르는 동안 그랩, 다른 버튼은 임시 스포이드. 원래 도구를 덮어쓰지 않는다. 접촉 중 전환/캡처 유실로 그림이 새로 생기지 않게 한다. | Windows가 보고하는 버튼 신호와 실제 드라이버 설정. 모든 펜이 두 버튼을 독립 전달한다고 가정하지 않는다. |
| 바깥 배경 | 캔버스 창에서 어두운 체크/지정 단색. 안쪽보다 조금 어두운 체크가 기본. 검은 외곽선과 바깥 그림은 유지한다. | PNG·스포이드·레이어 미리보기·Undo와 독립, 설정 재시작 복원 |
| 도구와 색상 재열기 복원 | 프로젝트별 편집 설정을 우선한다. 해당 설정이 없는 프로젝트는 마지막 전역 설정, 그마저 없으면 연필·검정 기본값을 사용한다. | 도구/세부 브러시/도구별 크기·농도·필압·경도·보정/앞뒤 색 복원, 다른 이름으로 저장 |

## 도구 설정 저장 원칙

- 도구 선택은 작품의 Undo 대상이 아니다. 임시 그랩/스포이드도 선택된 도구를 바꾸지 않는다.
- 프로젝트의 설정과 전역 기본값은 작품 픽셀·히스토리와 별도 기록이다.
- 프로젝트를 열어 복원했다는 이유만으로 전역 설정을 바꾸지 않는다.
  사용자가 설정을 바꿨을 때만 이후 새 작업의 기본값에 반영한다.
- 설정 읽기 실패가 작품 열기 실패가 되어서는 안 된다. 깨진 설정은 자동 덮어쓰지 않는다.
- 디스크 쓰기는 입력/렌더 hot path 밖에서 수행하며 대기열은 최신 값 하나로 합친다.

## 검증 상태

사용자의 작품과 설치본은 교체하지 않는다. 물리 펜과 창 없는 GPU 검증을 구분한다.

완료한 검증:

1. desktop 컴파일, desktop/paint-gpu/project-redb all-targets Clippy 및 색상환 JavaScript
   구문 검사 통과. vendored wry의 기존 lifetime 경고는 별개다.
2. desktop 핵심 회귀 검사 54개 통과, 명시적 실행이 필요한 4개 제외.
   빈 획 두 종류(필압 0/불투명도 0) 사이의 정상 획이 별도 프로세스에서도 정확히 재열린다.
   선택·변형·클립보드·잠금·Save As 등의 기존 작품 보존 검사도 통과했다.
3. 도구 설정 왕복/잘못된 설정 보존, Save As 설정 복사 검사 통과.
4. GPU batch의 진행 중 획 보존/부분 합성 금지 불변식 통과.
5. Windows, NVIDIA GeForce RTX 3080, Vulkan 및 DirectX 12, release의 `gpu_signed_workspace`
   readback 검사 통과: 14% 축소에서 atlas 한도를 초과하는 바깥 그림의 두 프레임 전체 표시,
   음수 좌표·보기 반전·회전, live/preview 취소 복원, 배경의 픽셀 저장 경로 격리.
   이는 정확성 검사이며 p50/p95/p99 성능 또는 실제 펜·최초 표시 지연 측정이 아니다.

6. `dx build --windows --renderer webview --package nyatidraw-desktop --locked --release`
   자산 포함 빌드 성공. 설치본과 분리한 임시 프로젝트/설정에서 Windows 창을 검증했다.
   실제 앱 backend는 DirectX 12였다.
   - 마우스로 SV 색 선택 → 2B/20px 획 입력 → 지우개 전환 → 연필 20px 복귀.
   - 수치 입력란 포커스 → 캔버스 획 → E 단축키가 입력란에 남지 않고 도구 전환.
   - 바깥 배경을 체크에서 단색으로 변경해도 그림·안쪽 체크가 유지됨.
   - 프로세스 종료·재실행 후 동일 root와 5개 타일, 2B/20px/선택 색/단색 배경 복원.
   - 명시적 Save로 PNG 출력 완료. 이후 임시 PNG 목적지를 디렉터리로 막아 실패를 재현하고,
     종료 안내의 프로젝트 다시 열기와 오류 확인 후 종료를 각각 마우스로 실행했다.
   - 잘못된 비어 있지 않은 임시 프로젝트에서도 오류는 캔버스에 한 번만 표시되고
     종료 안내를 마우스로 조작할 수 있었다. 파일 내용은 보존했고 강제 종료하지 않았다.
7. 종료 export 보수 후 최종 DX release 앱에서 새 임시 그림에 획 입력 → S 없이 종료를
   실행했다. PNG 생성과 writer 종료 후 정상 종료를 확인했다. 별도 프로세스에서 같은
   root/그림을 열고 Save한 PNG의 SHA-256이 이전 종료 출력과 같았다. 이어서 닫을 때
   `already-current`로 재인코딩을 생략하고 정상 종료했다. workspace all-features 테스트,
   project-redb no-default-features 검사, workspace all-targets/all-features Clippy,
   fmt 및 최종 자산 포함 release 빌드가 통과했다.

남은 확인: 실제 펜의 색상환/사이드 버튼/포커스 및 드라이버별 버튼 신호.
새 코드에 대해 물리 펜 검증, 고주사율 지연, Linux/macOS 호환을 확인했다고 주장하지 않는다.

## 검증 중 발견해 함께 보수한 종료 export

명시적 Save를 누르지 않고 닫으면 최신 PNG가 자동 예약되지 않던 경로를 보수했다.
실제 종료에서만 입력과 닫힌 획·완료 편집을 writer 순서대로 보낸 뒤 최신 PNG를 예약한다.
창/GPU 재생성에는 이 자동 요청을 추가하지 않는다. 같은 프로세스에서 성공한 export와
snapshot·파일 경로·크기·수정 시각이 같으면 다시 인코딩하지 않는다. 앱 재시작 후에는
이 임시 완료 기록을 신뢰하지 않고 새로 출력한다.

핵심 검사에서 Save 없이 종료, 앞선 Save 뒤의 획을 포함한 종료, PNG 목적지가 막힌 종료를
확인했다. 새 프로세스가 NTDR를 열고 출력한 PNG가 종료 출력과 byte 단위로 일치한다.
PNG 실패는 프로젝트 저장 실패가 아니며 종료창에서 별도 경고한다.
일반 종료에 파일 전체 compact를 넣지 않는다.

## 파일 크기 후속

실사용 작품의 원본은 변경하지 않고 복사본만 분석했다.
[저장 용량 진단](../storage-size-diagnosis.md)에 낭비 항목과 다음 측정 경계를 기록한다.
후속 승인 범위로 root 목록 무손실 압축과 기존 알파 파일의 일회성 재구성을 추가했다.
[ADR-0058](../decisions/ADR-0058-compressed-root-storage.md)의 백업·호환성·검증 경계를 따른다.
