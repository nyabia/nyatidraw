# iPad 웹판 입력과 편집 피드백

alpha.20에서 사용자가 Apple Pencil로 확인한 문제를 대상으로 한다. 로컬 Chromium의
터치·펜 입력 재현과 GPU 출력 검사는 실제 iPad Safari·Apple Pencil 감각 검증과 구별한다.

## 변경 계약

- **그림 이동:** 안내선만 그리던 경로를 원본에서 계산하는 실제 그림 미리보기로 바꾼다.
  한 화면 프레임에는 최신 위치만 계산하며, 손을 떼면 최종 위치를 한 번 확정한다.
  취소·도구 변경·화면 크기 변경은 대기 미리보기를 버린다. 미리보기는 저장·Undo에
  들어가지 않는다. [상세 동작과 보존 조건](web-artwork-move.md).
- **레이어 터치:** 손가락·펜의 행 터치는 선택, 세로 밀기는 목록 스크롤이다.
  순서 이동은 행 오른쪽 점 핸들을 끌어 시작한다. 마우스의 기존 행 드래그는 유지한다.
  클릭·그룹 펼치기·마스크 선택·이름 변경과 재정렬을 분리한다.
- **애니메이션:** 타임라인 닫기와 다시 열기를 제공한다. 닫기는 보기 상태만 바꾸며
  프레임·시간·히스토리를 지우지 않는다. 닫기 버튼은 가로 스크롤 영역 밖에 둔다.
- **아이콘:** 잘못된 상대 시작 좌표를 고치고 24×24 선 아이콘으로 통일한다.
  손 모양은 화면 이동, 네 방향 화살표는 그림 이동, 모서리 핸들은 변형이다.
  레이어 추가·삭제·마스크·잠금·클리핑·Solo도 구별하며 기존 단축키는 유지한다.
- **획:** round v6는 필압으로 줄어든 실제 접촉 크기에 맞춰 dab 간격을 계산한다.
  pencil v7는 필압이 크기·농도·종이 임계값에서 중복으로 사라지는 경로를 바꾸고
  픽셀보다 작은 펜촉의 면적을 적분한다. 강제로 최소 alpha를 넣지는 않는다.
  기존 엔진 1–5의 재생은 보존하고, 새 엔진을 모르는 리더는 명시적으로 거부한다.
  [브러시 설계](research/pencil-brush-design.md).

## Apple Pencil의 지우개 전환

Apple이 문서화한 몸통 더블탭·스퀴즈 처리 경로는 네이티브 앱의
[`UIPencilInteraction`](https://developer.apple.com/documentation/uikit/uipencilinteraction)이다.
[Pointer Events](https://www.w3.org/TR/pointerevents4/)에는 장치가 보내는 지우개 버튼 상태가
있지만, 이것이 Apple Pencil 몸통 제스처가 Safari에서 전달된다는 뜻은 아니다.
현재 웹판에서 이 제스처를 받을 수 있는 지원 경로는 확인하지 못했으며 이번 변경에는
넣지 않는다. 화면의 지우개와 E 단축키는 별개의 기존 도구 선택 경로다.

## 검증

Windows의 Edge/Chromium에서 1280×960 터치 화면을 설정하고 실제 웹 앱을 조작했다.
펜·손가락 입력은 브라우저 입력 프로토콜로 주입한 것이며, iPad Safari나 물리
Apple Pencil 검증은 아니다. 사용자의 작품 대신 별도 128×128 테스트 그림을 썼다.

| 항목 | 확인 결과 |
| --- | --- |
| 이동 중 표시 | 수정 전에는 누른 동안 빨간 그림의 화면 경계가 그대로였고, 수정 후에는 이동 중 경계와 놓은 뒤 경계가 일치했다. Undo 한 번으로 원위치가 되고 Esc 취소도 복원됐다. |
| 레이어 터치 | 행을 손가락으로 밀면 목록이 131px 스크롤되고 순서는 유지됐다. 펜 탭은 레이어를 선택했다. 점 핸들로 끌 때만 첫 두 레이어의 순서가 바뀌었다. |
| 포인터 캡처 | 핸들에서 행으로 캡처를 넘길 때 이전 대상의 `lostpointercapture`가 재정렬을 취소하던 문제를 실제 터치 재현으로 찾아 수정했다. |
| 타임라인 | 닫기·다시 열기 후 2개 프레임, 선택된 두 번째 프레임과 100ms 설정이 유지됐다. 닫기 버튼은 가로 스크롤과 분리되어 보였다. |
| 약한 필압 | 2H 연필 5px, 최소 크기·불투명도 0%에서 입력 필압 0.02와 0.05의 획이 저장 PNG에 남았다. 소프트 브러시 20px의 0.05 입력도 확인했다. 앱의 기존 필압 매핑을 통과한 합성 입력이다. |
| 저장·재시작 | 이동과 새 브러시로 그린 결과를 UI에서 PNG/NTDR로 저장했다. 브라우저 프로세스를 종료·재시작해 복구한 PNG의 RGBA8 픽셀이 종료 전과 완전히 일치했다. |
| 네이티브 재열기 | 별도 CLI 프로세스에서 웹의 두 NTDR 파일을 열어 PNG로 출력했다. 네이티브 출력은 16bit, 웹 출력은 8bit이므로 16bit를 반올림해 8bit로 정규화한 뒤 비교했으며 두 그림 모두 픽셀이 일치했다. 원본 NTDR은 변경하지 않았다. |

`cargo test --workspace --all-features --lib --bins --locked`, 워크스페이스
Clippy, 웹/복구 Worker의 WASM Clippy, 최종 `dx` 릴리즈 빌드를 통과했다.
기존에 무시하도록 지정된 데스크톱 테스트 5개는 실행된 것으로 세지 않는다.
파일 교체 검사는 샌드박스의 하드링크 제한 때문에 별도 테스트 파일로 다시 실행했다.
Rust 포맷, 레이어 입력 JS 문법, Git 공백 검사도 통과했다.

GPU 검사는 NVIDIA GeForce RTX 3080 / Windows / Vulkan / release에서 수행했다.
약한 필압 CPU/GPU 비교 160건의 최대 채널 차이는 3이었다. 선택 영역 검사 18건은
최대 차이 6으로 일괄 허용차 4를 통과하지 못했다. 허용차를 넘은 82개 픽셀은
동일한 CPU 계산 alpha를 고정 기능 GPU 블렌딩에 직접 넣는 대조 검사에서 재현되어,
선택 마스크 누락이 아닌 UNORM 누적 반올림 차이임을 확인했다. 해당 선택 영역
계약 검사는 통과했으나 완전한 CPU/GPU 픽셀 일치로 기록하지 않는다.

로컬 증거는 `output/playwright/ipad-feedback/`의 이동 전·중·후 캡처,
`layer-touch.png`, `timeline-reopened.png`, `pressure-live.png`, `reopened.png`,
테스트용 NTDR/PNG와 `target/ipad-*.log`에 있다. 이 생성 파일들은 Git에 추가하지
않는다. alpha.21의 게시 상태는 [배포 기록](releasing.md#alpha21-배포)에서 구분한다.
물리 iPad/Pencil의 필기 감각, Safari 입력 및 Apple Pencil 몸통 제스처는 미검증이다.

## alpha.21 공개 웹 확인

소스 `3c80749`의 [Website 게시](https://github.com/nyabia/nyatidraw/actions/runs/40709309453)
성공 뒤 기본 공개 URL에서 웹 본체·복구 Worker를 포함한 11개 파일을 CI Pages
산출물과 비교했으며 모두 일치했다. Windows 릴리즈가 진행 중인 첫 게시의
`release.json`은 당시 최신 게시판인 alpha.20을 가리켰다. 최종 다운로드 전환은
[배포 기록](releasing.md#alpha21-배포)에서 별도로 확인한다.

격리된 Edge의 1280×960 터치 화면에서 다음을 다시 확인했다.

- 그림 이동 중 빨간 영역의 화면 경계가 `[129,327,244,442]`에서
  `[250,390,365,505]`로 바뀌었고, 놓은 뒤에도 같았다. Undo 한 번으로 원위치가 됐다.
- 손가락 밀기는 레이어 순서 변경 없이 목록을 154px 스크롤했다. 펜 탭은 레이어를
  선택했고, 점 핸들 드래그만 두 레이어의 순서를 바꿨다.
- 타임라인 닫기·다시 열기 후 두 프레임과 두 번째 프레임 선택, 100ms 값이 유지됐다.
- 2H 연필 5px, 크기·불투명도 최소 필압 0%의 합성 입력 0.02와 0.05가 실제
  저장 PNG에 남았다. PNG/NTDR 저장 후 브라우저 프로세스를 종료하고 다시 열어,
  두 프레임 복구와 다시 출력한 PNG의 RGBA8 픽셀 완전 일치를 확인했다.
  테스트 PNG 픽셀 SHA256은
  `16979ffb7cf970a19aa1635b6af82f794a34e8bf09a5af03c9eb8aa58fc977c9`다.

증거는 로컬 `output/playwright/alpha21-public/`과 `target/alpha21-public-*.json`,
`target/alpha21-public-*.txt`에 있다. 콘솔에는 사이트 favicon 404와 Chromium의
Windows GPU powerPreference 안내가 있었으며 앱 오류 알림은 없었다.
이 결과는 공개 웹 검증이며 iPad Safari·물리 Pencil·Windows 설치 검증이 아니다.
