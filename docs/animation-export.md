# 애니메이션 스프라이트시트 출력 경계

`nyatidraw-editor::animation_export::export_sprite_sheet`는 고정된 전체 레이어 트리,
타일 스냅샷, 타임라인, 캔버스를 읽어 스프라이트시트와 프레임별 사각형·지속시간을 만든다.
타임라인 순서를 행 우선으로 배치하고 각 셀은 원본 페이지 전체 크기를 유지한다.
투명 여백을 자르지 않으며 마지막 행의 빈 셀은 투명하다. 같은 cel을 참조하는 held frame도
별도 frame 항목과 지속시간을 가진다.

CLI 사용:

```text
nyatidraw-cli export-spritesheet source.ntdr new-directory 4
```

열 수는 선택 사항이며 생략하면 프레임 수의 제곱근을 올림한다.
출력 폴더는 존재하지 않는 새 경로여야 한다. `sheet.png`와 `sheet.json`을 만들며,
PNG 인코딩과 sync가 성공한 뒤 JSON manifest를 마지막으로 게시한다.
manifest의 `x/y/width/height/duration_ms`는 숫자이고 128-bit frame/cel ID는 JSON
숫자 정밀도 손실을 피하도록 문자열이다. 위치는 왼쪽 위 기준 픽셀 단위다.
manifest가 없는 중단된 폴더는 완성 출력으로 취급하지 않는다.

기존 폴더·출력 파일은 덮어쓰지 않는다. 각 파일은 sibling 임시 파일을 완전히 쓴 뒤
배타적인 hard link로 게시하며, 지원하지 않는 파일시스템에서는 오류로 끝난다.
실패 정리는 이번 실행에서 생성한 파일과 빈 폴더만 대상으로 한다.
프로젝트는 `ProjectDb::open_read_only`로 읽으므로 export가 migration, retention,
복구 쓰기나 새 프로젝트 초기화를 실행하지 않는다. 복구가 필요한 파일은 먼저 편집기에서 연다.

한 변 최대 16,384 px, 전체 64 Mi-pixel이며 결과 픽셀과 한 프레임 임시 합성을 합쳐
320 MiB를 넘는 요청은 할당 전에 거절한다. 원본 타일/이력 및 PNG 압축기 메모리는
별도다. 동시에 모든 프레임의 dense 합성을 보관하지 않는다. 이 제한은 GPU나 게임
엔진의 최대 텍스처 크기를 보증하지 않는다.

기존 CLI `export-png`는 애니메이션 파일에서 저장된 active layer가 속한 cel의
첫 프레임을 선택한다. 유효한 active layer가 없으면 타임라인 첫 프레임이다.
다른 cel을 모두 겹쳐 하나의 PNG로 합성하지 않으며 원본 타임라인·Undo는 보존한다.

핵심 테스트는 프레임 순서·지속시간·투명도·빈 셀·원본 불변과 오버플로/자원 제한을
검사한다. GUI 내보내기 및 게임 엔진 가져오기 검증을 대신하지 않는다.

## 앱 연결

Windows 파일 메뉴의 `스프라이트 시트 내보내기`에서 이름을 선택하면 같은 이름의 새
`.frames` 폴더에 `sheet.png`와 `sheet.json`이 생성된다. 기존 폴더는 거절한다.
요청은 독립된 한 작업 슬롯에서 FIFO artwork worker로 전달되므로 요청 앞까지의
확정된 전체 트리·타일·타임라인을 읽는다. 출력 세대 확인과 manifest 게시가 함께 보호된다.
저장 대기 상태나 일반 PNG companion의 크기는 변경하지 않는다.

웹 파일 메뉴도 같은 공유 renderer와 manifest를 사용한다. 메인 스레드는 전체 checkpoint를
한 번 캡처하고 별도의 한 작업 Worker가 검증·프레임 합성·PNG 인코딩을 수행한다.
이 Worker는 autosave/IndexedDB 쓰기를 실행하지 않으며 완료/실패/시간 초과 후 종료한다.
출력 도중 다른 그림을 열면 이전 결과는 다운로드하지 않는다. 웹은 매 출력마다
`sheet-<UUID>.png`와 `sheet-<UUID>.json`의 같은 고유 이름을 사용하고 manifest의
`image`도 그 PNG 이름과 일치시킨다. 반복 출력 때 브라우저가 붙이는 `(1)` 등의 이름으로
새 JSON이 예전 PNG를 참조하는 문제를 피한다. 두 다운로드를 순서대로 요청하며
브라우저의 여러 파일 다운로드 허용이 필요할 수 있다. 브라우저가 둘째 파일을 차단했는지
앱은 감지할 수 없으므로 상태 문구는 두 파일 확인을 요청한다.
다운로드 완료와 저장 경로는 브라우저가 관리하므로 앱 상태는 요청 완료까지만 표시한다.

두 UI는 재생·획·변형·색 보정 중에는 시트 출력을 거절한다. 기본 열 수는 공유 구현의
제곱근 올림이며 원본 편집 상태와 Undo를 변경하지 않는다. 픽셀/메타데이터 순서와
게시 알고리즘은 세 호스트에서 중복 구현하지 않는다.
